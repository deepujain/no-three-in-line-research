# Lower-memory fallback: exact orbit backtracking with reversible secant blocking

Prepared 2026-11-27 by Literature Researcher / Mathematical Reviewer, gpt-6.1-terra/high per parent assignment. This is a design proposal, not an implemented, benchmarked, or novel algorithm. No numerical model build or search was run in this review.

## What the primary sources establish

[Prellberg, arXiv:2602.07751v1, §§2–4](https://arxiv.org/html/2602.07751) formulates line capacities and the odd-grid near-quarter-turn (`rct4`) family: quarter-turn four-orbits away from both diagonals, one half-turn pair on the main diagonal, and an empty anti-diagonal. The paper builds weighted orbit line constraints, reports exact full witnesses through n=60 and explains that a smaller formulation is not necessarily a fast solve. Its §5.5 reports no reliable improvement from several guiding and warm-start choices in the experiments performed; that observation does not prove other search organizations cannot help. The paper does **not** claim the backtracker below is its solver.

[Flammenkamp's database readme, §§State of the Art 1997 and About the implemented Algorithm](https://wwwhomes.uni-bielefeld.de/achim/no3in/readme.html) describes its historical method as a branch-and-bound tree search and stresses traversal order and symmetry effects. This supports considering tree search as a documented technique, but the proposed implementation and performance predictions below are our inference, not a description of that program. The database and [the approved n=71 fixture](../data/published-n71-rct4.json) supply a known valid member for testing, not evidence that n=79 will be easy.

The existing local `data/near-quarter-preflight-n79.json` records that the full reduced SAT build hit its sampled 256 MiB RSS gate after at least 2,560,687 clauses; `build_complete=false`, with no solve and no candidate. The weighted-line enumeration itself was reported complete, but the stopped CNF is not a complete formula or impossibility result. This is a concrete reason to investigate a bounded-live-state alternative.

## Proposed mechanism, not a reported source result

Use depth-first branch-and-bound over the **same approved n=79 near-quarter-turn orbits**, but enforce geometry immediately while extending a partial point set, rather than storing all line inequalities or a growing set of learned SAT cuts. Maintain:

1. The selected complete orbits and the actual points they expand to, with row and column occupancies. Select exactly 39 four-point orbits and one diagonal pair for the 158 target.
2. A per-grid-cell integer `blocked[p]`: the number of unordered pairs of currently selected points whose Euclidean line contains p. To add an orbit, first reject any point already blocked, any row/column capacity violation, or any collinear triple internal to the new orbit. Insert its points one at a time; for every new pair with a previously selected point, enumerate the **entire maximal grid line** using primitive integer direction and increment the relevant cell counters. Before accepting each subsequent point, require its current count to be zero. This also checks cross-triples involving multiple new-orbit points. Undo in reverse insertion order, decrementing exactly the increments attributable to the removed point's pairs.
3. Choose an underfilled row with the fewest currently admissible remaining orbits intersecting it, and branch over **all** such orbits. Prune if no feasible remaining orbit can fill the row, if a column cannot reach its required load, or if the remaining orbit-type counts cannot reach 39 and 1. A stronger bipartite matching or flow relaxation may be added only after proving it cannot discard feasible orbit completions; it is not required for the first implementation.

Completeness argument, conditional on implementation: a full valid extension must contain an unselected orbit that contributes to each currently underfilled row. Branching over every admissible such orbit cannot omit that extension; pruning may use only necessary capacity bounds. Different insertion orders can reach the same set, so ordering may be chosen deterministically or symmetry-broken only with a completeness proof; merely skipping already visited states without a complete key and careful backtracking is unsafe. Check full solutions with both existing exact geometry verifiers and the independent symmetry/map checks. Exhaustion would concern this **restricted family only**, and would require independent replay or another checkable certificate to support a formal UNSAT claim. A timeout or node limit proves nothing about feasibility.

This mechanism can reach configurations far from the 78-grid seed without a deletion limit; unlike lazy SAT, it rejects conflicts in partial states and keeps no unbounded global cut database. It trades learned-clause propagation for explicit branching and potentially expensive geometric updates. It may be much slower, and no paper data or local experiment establishes which method wins.

## Target 157

The proposed n79 `rct4` branch has half-turn invariance. An odd-cardinality half-turn-invariant set with more than one point contains the center and an opposite pair, which are collinear. Thus this exact branch cannot find 157 and should not be advertised as a 157 search. A **different, separately verified adaptation** can use the same secant counter with unrestricted cells or with diagonal-reflection orbits, for each possible deficient row and column; in the diagonal-reflection family the two deficit indices coincide. Branching must use exact load one for the chosen deficient axis and two for all others, and account for singleton diagonal orbits. A 157 witness needs both validators and current literature checks; exhaustion of one deficit or symmetry slice is not global UNSAT. No performance claim is made for that adaptation.

## Memory and correctness gates

At n=79, the grid has 6,241 cells. A packed unsigned 16-bit blocker counter uses 12,482 bytes: at most C(158,2)=12,403 selected pairs contribute to any one counter, so this width suffices if updates and undo are exact. Occupancy, row/column counts, the 1,560 orbit definitions/IDs, and a DFS stack are additional bounded state. Along one root-to-leaf path, updating each newly formed pair over at most 79 grid cells entails at most 79*C(158,2)=979,837 counter increments; a fully retained 16-bit cell-index undo log would be under 1.9 MiB plus offsets, whereas recomputing reverse updates from the chosen orbit stack can avoid retaining such a log. These are **packed-array arithmetic estimates only**, not Python or process RSS measurements. Python integer/list/set overhead, temporary buffers, DFS frames, code and OS allocations can be far larger. Repeated nodes multiply time, not this bounded path-state estimate; avoid a global visited-state or clause cache unless separately bounded.

Before any n79 run:

- Prove and test every update and undo against a fresh pair-line reconstruction on **every** reachable partial orbit assignment at n=3,5,7, including vertical/negative slopes, line endpoints, point pairs inside one new orbit, overlapping secants, rejection without state mutation, and counter nonnegativity/overflow. Confirm all branching and row-bound prunes preserve the exact small-n feasible set by comparison with brute-force expanded assignments and the independently reviewed weighted-line model. Do not test only successful leaves.
- Inject the verified n71 fixture's orbits as a controlled sequence of additions, validate counters after each add/undo, and restore the empty state. This is a geometry regression, not a search or expected runtime benchmark. Check both geometry verifiers on any full candidate.
- Benchmark against existing methods only in an authorized separate worker slot, under equal measured operation/time limits and a host-enforced RSS limit. Start with known solved odd sizes and report nodes, branching/dead-end counts, per-node work, wall time, measured peak RSS and full certificates. A reasonable initial stop gate is ≤30 seconds and ≤256 MiB per preflight process, with aggregate guard margin. The estimate above is not measured evidence of meeting that gate. Do not launch an n79 search merely because tiny tests pass.

Do not copy branch-specific restrictions or blocking states into an unrestricted SAT geometry checkpoint. Document source and model hashes, deterministic traversal ordering and parameters, and distinguish complete tree exhaustion from a partial run. All performance and novelty questions remain open.
