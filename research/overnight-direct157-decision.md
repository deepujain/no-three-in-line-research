# Direct 157-point route: decision

**Decision: do not allocate a new unrestricted SAT run on the current evidence.** It is a mathematically credible direct-157 route outside the closed seed-repair neighborhoods, but the retained observations do not show a credible computational advantage under this pilot's resource and time constraints. Keep it as a separate future option rather than repeating an expensive failed configuration.

The existing `src/lazy_sat.py --target 157` represents the 6,241 real n79 cells with Boolean variables. Each row and column has capacity at most two; independent one-hot deficit indicators enforce exactly one row and one column of load one and all others load two. Their intersection may be occupied. Native SAT proposes an axis-valid assignment; exact geometric separation adds only genuine collinear real-cell triples as cuts, and both integer verifiers must accept any emitted candidate. This unrestricted representation does not depend on the 158-only near-quarter family or the published seed. A valid 157 candidate would improve the verified local 156-point baseline, but is neither an optimality proof nor an automatic novelty claim.

The separately reviewed axis encoding and its seven small-instance tests exhaust n2..4 real-cell assignments and include a valid n3 five-point case with occupied deficit intersection. The decisive correctness gate for any changed implementation is to compare all projected satisfying sets with an independent determinant/axis oracle at n2..4, including that occupied intersection and both dual verifiers. The saved tests already support the reviewed earlier encoding; they do not prove the current enlarged dispatcher source or n79 memory behavior without checking its exact source and rerunning the relevant tests. Current local `.venv` imports PySAT `1.8.dev24`; this read-only import is not a solver run. Current entrypoint SHA-256 is `b71eb696b1a181886f745ec27d9d6e7ad2a47e5d22380c1ecdef7038ed0e5db2`; separately retain exact wrapper, dependency and verifier pins if reconsidered.

The previous unrestricted target-157 Minisat22 run was terminated at the shared aggregate 1,536-MiB RSS gate after about 812 seconds, without an accepted witness or UNSAT result. A diagonal-reflection target-157 SAT run also ended at that aggregate gate after about 155 seconds; aggregate termination does not identify its individual RSS. Their historical checkpoint files are about 144 MiB and 40 MiB respectively and may have an interrupted tail; neither should be loaded or reused without independent validation and exclusive ownership. These are failure observations, not proofs that 157 or SAT is impossible. The remaining approximately 5,800 seconds is an accounting budget, not evidence that a fresh 256-MiB n79 SAT instance can fit or that it will solve.

Reconsider only if a concrete change or independent bounded measurement shows lower memory and useful candidate progress: rerun the exact tiny correctness gate, then a fresh-path, tightly cut-limited and source-pinned actual-host build/search under the existing owned 30-second/256-MiB gate, recording construction, cuts, candidates, cleanup and total RSS. Stop on timeout, cap or bad receipt; do not silently reuse a large old cut file or extend the run. Compare outcomes and whole-process cost against a justified alternative before allocating sustained time. The already-reviewed reflection row-batch DFS also directly targets 157, but continuing its unchanged explored frontiers is not a new route and its restricted family can miss nonsymmetric solutions. No numerical search, code change, or new proof was performed for this memo.
