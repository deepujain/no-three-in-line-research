## Recommended next check, requiring design/source review first

Prefer one independent **monotonic RUP** check of these exact saved bytes before designing RAT support. A new stdlib-only checker would retain the original clauses and every previously checked RUP addition for inference. Deletion records would still be parsed and checked against a separate exact active multiset, but would never remove an inference clause. No clause, proof line, order, variable, CNF identity or old receipt would be edited. This is a different, explicitly reviewed certificate criterion; it is not a silent change to the frozen checker.

Soundness is direct: original clauses are entailed by the original formula. A RUP addition is entailed by the retained database; by induction that database is entailed by the original formula. Thus every retained addition is original-formula-entailed. A checked empty addition proves the original formula UNSAT. Ignoring deletions for inference preserves this induction. All remaining proof records and exact hashes still need validation; a raw solver result never substitutes for the final checked empty clause. No RAT, fresh variables, search, assumptions to a solver or proof conversion belongs to this proposed check.

Use an independent propagation implementation, for example positive/negative integer bit masks with repeated clause scans, rather than copying the frozen literal-dictionary loop.
