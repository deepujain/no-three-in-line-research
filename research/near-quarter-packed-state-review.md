The full source and tests implement the reviewed design's essential state contracts. Strict odd-grid bounds and two-byte unsigned width checks precede grid-dependent allocation. Canonical orbit construction preserves the frozen tuple order; the packed view avoids a second permanent tuple map and point-to-variable dictionary. The binary map digest matches the existing v1 convention. The existing expansion and both geometry verifiers accept the minimal view. Source inspection and arithmetic support the declared n<=79 representation bounds, but actual resource behavior beyond n7 remains unmeasured.

The line routine computes maximal primitive integer lines. Insertion increments each unordered selected-point pair's line exactly once, including endpoints; queries apply only to fresh cells. Occupancy, row/column limits, selected-orbit uniqueness and four/pair type caps precede additions. The selected-point ceiling gives the 12,403 blocker bound at n79. Every increment/decrement checks width or positivity; physical-counter overflow also poisons the state rather than becoming a pruning outcome.

`PointProgress.previous_index` counts completed pair lines and `next_cell` the completed prefix of the current line. Cancellation while building a new line or before an update leaves sufficient progress to reverse exactly the committed increments. Point metadata commits only after the final check. Orbit metadata commits only after every point succeeds and its own final check. Geometry rejection reverses the incomplete point and all new committed points. Unexpected forward failures poison the component; inverse failures mark it unusable and prevent retry of an already partly executed inverse. Such fatal failures never authorize checkpoint saving or continuation.

The owner contract is material: ordinary `pop()` may stop before mutation, preserving the child. Once inverse work starts it finishes the bounded inverse, latches any `PackedStop`, commits point/orbit metadata and returns normally. The owner must then commit the corresponding frame change before calling `raise_latched()`. Owner cleanup after a successful first orbit and failed/interrupted second orbit must use `rollback_last_orbit()`, which can finish with an already expired or latched budget. Calling ordinary pop in that situation would risk stopping before rollback. Unexpected polling errors during inverse are retained, cleanup proceeds, and the state is poisoned. These guarantees address cooperative `PackedStop` checks, not arbitrary asynchronous process death or memory corruption.

The geometry snapshot includes blockers, occupancy, both axes, full zero-padded point/orbit arrays, counts, type counts and pending/poison/latched flags. Physical work and callback identity are intentionally separate. `assert_checkpointable()` refuses poison, pending operations and unpropagated stops. Future integration must invoke it, preserve the full live/replayed snapshot comparison, bind the actual map/source identity, enforce adapter2 first-event mode and closed constructor selection, and review all scan/push/pop/frame commit boundaries. The reviewed historical core `51a8fcde5772990be1b0de53ac8e04b30c8254dd4267e335186be8fbd84462a2` and codec `26a31dc66144745a0c3cf0f5a7976eee78e1fcc9abc8844d1c4d039d14e5bb4c` were unchanged at this review.

Independent verification: `.venv/bin/python -m unittest tests.test_near_quarter_packed_state -v` passed all nine tests in 2.099 seconds. The tests cover all 4/64/4096 tiny orbit subsets, 4/17/100 valid partial sets and 8/102/1200 extensions against frozen geometry and integer determinant oracles. Every grid pair at n3/n5/n7 (1512 unordered pairs, both directions) matches the determinant-defined line. The map/digest and dual-verified complete-set counts 1/0/0 agree. Fault tests cover 170 construction boundaries, 509 representative point/orbit push boundaries, 118 valid-prefix pop-latch cases and 1164 owner pair transactions, including 990 second-orbit rejections. Poison cases include overflow, underflow, unexpected poll/forward failure, work-counter overflow and a failed partial-point inverse attempted only once.

I additionally checked every callback boundary for rejected pushes `(n=5, prefix=(6,), orbit=2)` and `(n=7, prefix=(12,), orbit=7)`: all 64 sticky-stop boundaries restore the exact entry snapshot. I checked all 105 callback boundaries for pops from n3 selected `(1,2)`, n5 `(1,)` and n7 `(1,)`: a stop at the initial check preserves the child, while later stops finish the exact parent geometry and remain latched until explicit propagation. All saved evidence source hashes match current files. These are tiny correctness tests, not throughput measurements.
