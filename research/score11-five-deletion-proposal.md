# Score-11 repair with up to five deletions

The fixed source and dual geometry prerequisites match `score11-cover-repair-proposal.md`. The independently reviewed arithmetic report `data/score11-cap5-arithmetic-review.json` is pinned by bytes. The source rechecks all conflict triples and recomputes all minimal covers through size five, requiring the three previously audited size-three covers and no others. Every deletion set through size five that can leave a valid retained set contains one of these covers. Each cover plus zero, one or two source points enumerates all such sets; deduplication yields 3 size-three, 462 size-four and 35,344 size-five sets, 35,809 total. Non-hitting sets cannot be repaired by insertion because an old triple remains.

For each deletion set, reuse the frozen repair routine: eligible additions lie in freed rows and columns, at most 5²=25 cells, are checked against retained points and each other, and must reach 157 or 158 points. Every survivor is independently dual-verified and immediately saved. Timeout produces an explicit incomplete report with the number of completed deletion sets, without a closure claim or resume promise. The bounded set of deletion sets is retained for deduplication; it is not a visited-state search history and is not a measured process memory bound.

The proposed run is one shared 25-second soft interval enclosed by the existing 30-second / 256 MiB owned guard, including source verification, candidate generation and output. Memory fit, full completion and success are unproven. No n79 execution before independent source and tiny-test review plus lead allocation. Any complete negative result concerns only at most five deletions from this specific source and the permitted additions.
