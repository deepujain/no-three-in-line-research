# 157-point deficiency walk: design for review

Status: design only; no new implementation, n=79 scoring, formula, or search was performed for this proposal. Mathematical review and independent source/tiny review precede any owned actual run. This is an exploratory search, not an exhaustive proof.

## Prior work and motivation

A targeted repository search for deficient-axis relocation and 157-point walkers found no equivalent general deficiency walker. `src/trade_search.py` represents exactly 2n points as two permutations and its `degree_two`/`decompose` require every degree to be two; its uncolored rectangle proposal and sequential exact delta do not require that full-state representation. `research/rectangle_barrier.py` explores full-degree rectangle components; `research/review_one_hole.py` exhausts a different boundary-extension family from a 156-point seed. `research/diagonal-secants.md` searches a reflection-symmetric 157-point family, not this unrestricted walk. This is a targeted code and record search, not a claim about all possible prior work or literature novelty.

## State and initialization

For n >= 2 a state is a set A of exactly 2n-1 distinct grid points with row and column degrees at most two. The degree sum forces exactly one row r and one column c of degree one, all other degrees being two. They need not intersect in an occupied point. Score is the exact number of collinear triples, including multiplicity on lines with four or more points. Invalid states are legitimate search states, never certificates.

Read and hash-check the fixed source `data/trades-n79-seed270079-state.json`; verify its 158 distinct in-bounds cells, degree two on each axis, and score 11 using both independent validators before use. Choose the source point with maximum number of incident forbidden triples, breaking ties by lexicographically smallest (row, column). Delete it. Because the source has at least one triple, the resulting 157-point score is at most 10; its exact score and identity require the future owned run and dual validation. Initialization on tiny fixtures uses their actual n and score, without assuming 11.

## Reversible moves and score

1. Row relocation: choose an occupied (u,v) with u != r and unoccupied (r,v); replace (u,v) by (r,v). Column degrees are unchanged; the deficient row becomes u and c is unchanged. Column relocation is its transpose: choose (u,v) with v != c and unoccupied (u,c), replace it, and the deficient column becomes v. Reject occupied destinations. Both moves preserve cardinality, uniqueness, and all axis degrees and have a legal inverse.
2. Rectangle: choose two occupied cells (u,v),(s,t) with distinct rows and columns and both crossed cells unoccupied; replace them by (u,t),(s,v). All axis degrees, including the positions of both deficiencies, are unchanged. This is the existing uncolored `rectangle_proposal`, used read-only after verifying its input assumptions. Each accepted rectangle has a legal inverse.

For relocation remove the old cell, subtract `point_conflicts(old, remaining)`, then add `point_conflicts(new, remaining)`. Existing `point_conflicts` groups unoriented primitive directions and counts pairs on each line. For rectangle use its existing sequential remove/add delta. Each affected triple is counted exactly once even if multiple moved points participate. The implementation must assert or test source/destination membership before calling this helper; it does not itself validate membership or bounds. Keep exact integer scores and reject any inconsistency with full recomputation. No D<=8 bound or other retention constraint applies to any state, including transients.

## Bounded exploratory algorithm

Use one fixed seed (proposed 279157) and a local `random.Random`; sorted point lists and explicit stable ordering avoid hash-order dependence. Each proposal selects row relocation, column relocation, or uncolored rectangle with probabilities 1/4, 1/4, 1/2 respectively. Choose uniformly from sorted occupied points, or uniformly from unordered pairs of sorted occupied points; reject illegal choices as attempted proposals. Use fixed-temperature Metropolis acceptance: accept nonpositive score deltas, and positive delta d with probability exp(-d/2). Uniform acceptance samples come from the same seeded RNG. This deliberately permits uphill transitions and has no score barrier or deletion restriction. Keep only current and lowest-score validated state, without an unbounded visited set, beam, checkpoint, or restart. A seed fixes the proposal stream for a fixed implementation/runtime and iteration budget; a wall-clock cutoff does not guarantee equal iteration counts or cross-platform bitwise reproducibility.

A future single run has a 25-second monotonic soft deadline in the existing owned 30-second / 256-MiB guard; the owner must separately authorize and allocate it. Set and document a finite proposal cap before execution, and stop at either cap or soft deadline; no automatic retry or extension. Check time between proposals and before beginning each expensive validator, allowing the outer guard to stop overruns. Report attempted, legal, accepted and per-move counts, best validated score, reason stopped, elapsed time and guard result. Timeout, guard failure, or a stopped walk gives no exclusion or optimality result. The guard's sampled peak memory is not a strict instantaneous bound.

## Durable output and validation

Before recording an incumbent, independently validate its sorted certificate with both slope and determinant validators; require matching normalized hashes, point counts, empty parsing errors, equal conflict counts and equal conflict triples after canonicalizing point coordinates. Also explicitly verify 2n-1 distinct in-range points, every row/column degree <=2, and the uniquely deficient axes. Save exact score, points, normalized hash, source identity, removed initialization point, seed, move/acceptance parameters, software pins and both reports atomically. Save initial validated invalid incumbent and each strictly lower validated incumbent; report only a fully validated saved incumbent, not a provisional running score. If both validators have already established a valid witness, save it immediately even if the soft deadline has elapsed; stop after saving. On disagreement, write a failure receipt and stop, with no validity or exact-score claim. If time expires before a second validation starts, do not call an unverified state a new incumbent. A crash or hard guard stop must not turn a partial write into a complete receipt.

If score zero, preserve a standalone 157-point certificate and both independent verification reports. A 157-point witness improves the existing verified 156-point local baseline, but is not an optimality or novelty proof. A positive score remains an invalid search state, even if it improves the starting score.

## Required review and tests before an actual run

Source/tiny review must verify that implementation matches this contract and test: exhaustive legal/illegal relocations and rectangles on small deficient states, inverse moves and axis invariants, deltas against independent determinant recomputation (including lines of four), deterministic proposal prefixes, maximum-incidence lexicographic tie, occupied-destination rejection, no retention filter, validators' mismatch, initial and improved invalid persistence, verified witness saved across deadline, and soft/outer guard failure behavior. Tests must use tiny boards only. Pin the implementation, tests, dependencies, source, reviews, and guard before the lead decides on any actual allocation.
