# Proposed next exploration: odd-grid near-quarter-turn orbit model

Prepared 2026-11-27. Literature Researcher; inherited gpt-6.1-terra/high per parent assignment. This is one proposed experiment, not a newly discovered construction or a claim of numerical progress. Sources accessed 2026-11-27.

## Verified source facts and scope

[Prellberg, *Constraint Satisfaction Programming for the No-three-in-line Problem*, arXiv:2602.07751v1, §§2–4](https://arxiv.org/html/2602.07751) gives an odd-grid construction family that is invariant under half-turns and uses quarter-turn orbits **away from the diagonals**, with one two-point main-diagonal orbit and an empty anti-diagonal. It is not invariant under a quarter turn as a whole. The paper formulates line constraints with orbit multiplicities, and reports 2n witnesses for all n≤60, using this reduced family for the odd instances. Its February frontier is superseded by later records. The [author's CP-SAT code](https://github.com/ThomasPrellberg/no-three-in-line---CP-SAT) is available as a reference; this proposal does not assume its exact implementation is installed locally.

The [Flammenkamp record history](https://wwwhomes.uni-bielefeld.de/achim/no3in/readme.html), dated 2026-11-22 and accessed 2026-11-27, attributes first n=71 and n=73 solutions in the `rct4` class to Heule in August 2026. The [construction directory](https://wwwhomes.uni-bielefeld.de/~achim/no3in/download/configurations/) contains `n71_rct4.few` and `n73_rct4.few`. The database's October table supplies the n=78 full witness but does not list a full n=79 witness; absence from that table is not proof that no other witness exists. Fresh novelty checking is necessary before claiming priority.

At odd n=79 the verified row bound is 158. A valid 158-point candidate would prove D(79)=158; a failed run in this restricted family does not prove nonexistence for other families or grids. This family cannot yield the 157 target: it is half-turn invariant, and any odd no-three-in-line set of more than one point cannot have that symmetry.

## Proposal: compile the orbit model once and solve it directly

Use the paper's odd-grid family, rather than allowing arbitrary half-turn-invariant sets. The existing exact quarter-turn branch was pruned by parity, but this near-quarter-turn family was not: its exceptional diagonal pair makes it half-turn invariant without being quarter-turn invariant. For n=79, forbid the anti-diagonal and introduce one Boolean for each four-point quarter-turn orbit disjoint from both diagonals and one for each two-point half-turn orbit on the main diagonal. There are 1,521 off-diagonal orbit variables and 39 main-diagonal-pair variables (1,560 total). Target 158 is equivalent to choosing 39 four-point orbits and one two-point orbit; enforce the exact row/column occupancies as well. This automatically explores point sets that can differ extensively from the published n=78 seed, without restricting the number of seed deletions or using the permutation-trade neighborhood. It is nevertheless a strict subfamily of the existing half-turn branch, so it may discard every solution at n=79.

For each maximal grid line L, construct the coefficient c(L,o)=|L∩orbit(o)| and impose `sum(c(L,o)*z[o]) <= 2`; include all directions. Coefficient multiplicity matters: coefficients ≥3 forbid that orbit, a coefficient 2 can coexist with no other positive term, and coefficient-1 terms have at-most-two capacity. Stream line generation and canonicalize/deduplicate identical weighted incidence vectors where affordable. Because odd-grid family configurations are guaranteed half-turn invariant, an optional *proved* line-orbit quotient can keep one line per half-turn orbit; do not quotient by quarter turn, which need not preserve the two diagonal points. The same care applies to rows and columns. An exact solver can consume weighted constraints natively or use a verified compact cardinality encoding. The locally available optional PySAT supports SAT infrastructure; a suitable weighted compiler must be implemented and measured. OR-Tools is not assumed installed; the paper used CP-SAT and its reported throughput is not a performance forecast for this machine.

This differs from current candidate-driven lazy SAT: the solver begins with complete reduced line capacities and propagates from them immediately instead of accumulating millions of witnessed three-cell cuts. It also differs from using generic half-turn equality clauses: the small decision set and off-diagonal quarter-orbit restrictions are a stronger, deliberate structural hypothesis. Full line constraints may still be too expensive; a restricted model is not automatically faster. Do not copy branch-specific orbit clauses into the unrestricted geometry checkpoint. Solver UNSAT would be only for this `rct4` family, and requires correct model and solver proof for any formal exclusion. A timeout is inconclusive.

## Gate before any n=79 search

1. Implement only a reusable orbit map and streamed weighted-line compiler first. For odd n=3,5,7, exhaust every orbit-variable assignment and compare the compiled row constraints and weighted line conditions with independently expanded points checked by the brute-force determinant verifier. Explicitly include lines with coefficients 2 and ≥3, both slope signs, center and diagonal edge cases, and check that half-turn line quotient preserves outcomes. Use unrestricted line generation as the oracle, not a second copy of the quotient code. Check arbitrary row/column occupancy before imposing the 2n target.
2. Start with n=3, the smallest odd size with a full 2n witness: the primary paper’s Theorem 1 states existence for all n≥2 through 60, and its §3 / Table 2 specifies the odd-grid orbit model at n=3. A concrete fixture is {(0,0),(2,2),(0,1),(1,0),(1,2),(2,1)}, the valid six-point half-turn example in `research/symmetry-next.md`; it lies in the stated near-quarter-turn family (anti-diagonal empty). Check it with both exact checkers and the compiler. Also decode the primary n=71 or n=73 rct4 file and independently verify its full coordinates and membership in the model; that is a regression fixture, not an n79 result. These tests detect mismatched orbit domains and wrongly deduplicated weighted lines.
3. Under a separately approved scheduling slot, benchmark equal single-core, bounded runs against the existing generic half-turn lazy SAT on the **same odd n and target**, including a small solved instance and n=79 build-only preflight. Record generation/encoding seconds, constraint/variable counts, peak RSS, initial build success, exact candidates validated, and solved/timeout status. Use the same explicit wall/operation budget and nonoverlapping resources. A reasonable first gate is no more than 30 seconds and 256 MiB measured peak RSS per preflight worker; these are proposed guardrails, not measured requirements. Proceed only if the exact small-model checks pass, the known fixture is accepted, and the n79 model fits within the agreed allocation with margin for other active processes. If it fails the gate, stop and report the observed limit rather than silently dropping line constraints.

## Memory estimate and risks

There are 6,241 original cells but only 1,560 orbit decision variables at n79. The already measured unrestricted line generator yields 1,644,284 maximal lines and 6,253,052 point incidences (`data/line-model-n79.json`). As a deliberately loose storage estimate, representing every original incidence as two 32-bit integers (orbit ID and coefficient) plus one 32-bit line-offset array would take about 56.6 MB decimal (54.0 MiB), before duplicate aggregation. This is an upper-count illustration for packed raw incidence arrays, not a full model, and it is not a prediction that a Python or SAT/CP-SAT backend fits in the 256 MiB gate. Solver clauses, auxiliaries, weighted-constraint lowering, temporary Python objects, allocation overhead, and any deduplication hash table can greatly exceed it. Stream/count before export; do not build full Python object graphs or an uncontrolled per-triple CNF. Memory, solver availability, and feasibility at n79 remain unverified.
