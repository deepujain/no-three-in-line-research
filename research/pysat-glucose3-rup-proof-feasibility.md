# Installed Glucose3 proof feasibility: tiny evidence only

Feasibility result: the installed `python-sat`1.8.dev24 Glucose3 backend can emit textual DRUP, and a separate standard-library Python RUP checker validated tiny emitted UNSAT proofs. This does not upgrade any n79 native result to proof-checked status. No n79 solve/replay, installation or network access was performed.

Installed `pysat/solvers.py` documents `with_proof=True` and exposes `get_proof()`. The Glucose3 wrapper uses a temporary proof file and decodes its lines as ASCII. Its constructor rejects simultaneous `incr=True` and proof tracing. A concrete ordering caveat was confirmed: bootstrap clauses are added before tracing is enabled. Bootstrapping `[1],[-1]` returned UNSAT with an empty proof. Constructing an empty proof-enabled solver and then adding both clauses produced `0` followed by a deletion record, which the checker accepted. Future proof work must enable tracing before inserting any input clause.

The nontrivial tiny fixture is all eight sign combinations of three variables. Glucose3 emitted `2 3 0`, `3 0`, `1 0`, `0`. The checker independently validated every addition by negating that clause and performing unit propagation against the current clause multiset until contradiction. It processed deletion records, rejected absent deletions and malformed/out-of-domain literals, and required a checked empty clause. Five negative cases were rejected: false empty proof for a satisfiable formula, the cube's empty clause without necessary learned steps, missing final contradiction, invalid literal domain and nonexistent deletion. A separate synthetic deletion fixture also passed. This checker uses no SAT library; only the fixture producer imports Glucose3. It is a feasibility implementation, not a formally verified checker or a production proof pipeline.

Persistent source: `research/tiny_rup_feasibility.py`, SHA-256 `fc278d8317bc4e96b23aa1e337de05c676d76ad86a58ced09a4346ebc31aabff`.

The installed environment's proof-related package inventory contains only python-sat. This is a bounded PATH/environment inventory, not a claim that no such executable exists anywhere on the machine.

## One prospective auditable follow-up

After separate source/tiny review and coordinator allocation, use the already accepted main19 pair-only relaxation as a first small proof-producing scope. Recompute its fixed prefix, full102-orbit mask, all5,151 pair decisions, radius formula and1,445 exclusions; require exact agreement with the accepted independent audit. Save the exact deterministic DIMACS CNF and its SHA-256 before solving. This scope has555 variables,2,427 clauses and5,172 literal entries. It contains only exact degree constraints and independently justified binary exclusions, with no lazy clause insertion after the solve starts.

Construct empty `Glucose3(with_proof=True)` without incremental mode, insert the saved CNF, and solve once. Native SAT stops as an inconclusive pair relaxation; no geometric witness follows from that SAT assignment. Native UNSAT permits proof checking, but is not promoted until the independent checker accepts a derived empty clause against the exact saved CNF. Do not reuse an earlier native answer or a proof from another formula.

Concrete proposed caps: one25-second shared soft budget and30-second owned/256-MiB hard guard; at most5 seconds for native solve and10 seconds for proof checking, each also bounded by the remaining shared budget. Require the exact555-variable/2,427-clause input. Cap the raw proof at2 MiB,50,000 records and at most555 literals per clause; cap checker work at50 million literal inspections as well as wall time. Check size before materializing proof lines. Enforce the raw trace's file size in the owned child, for example with a2-MiB `RLIMIT_FSIZE`, so tracing cannot silently grow without bound. If that limit terminates the producer, accept no proof result. Record every cutoff as incomplete; no retry or expansion is automatic.

The production checker needs source review, strict bounded parsing, canonical clause-multiset semantics, per-loop deadline/work checks and fail-closed rejection of unsupported proof steps. Persist the exact CNF, raw DRUP, source/input hashes, checker receipt and gate receipt. Independently validate the geometric mapping and degree encoding as well as the Boolean proof; a correct proof certifies the supplied CNF, not a different scope. This proposed experiment is not allocated or executed by this feasibility note.
