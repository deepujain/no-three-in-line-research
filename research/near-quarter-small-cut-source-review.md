# Small radius cut: independent mathematical and pure-source review

Decision: approve the pure helper and exhaustive tiny tests. No packed integration, frontier migration, n79 allocation or speed claim is approved by this review.

Proposal SHA-256 `ff88a27cd773ce388decadab7389aceaa08b5ffadeee914b21cda4d15b6e55d6`; helper `research/near_quarter_small_cut.py` SHA-256 `f04208905c8af6010ac09a3c8f789177719760a0019f4ef259ee8f93b3b97b54`; tests `tests/test_near_quarter_small_cut.py` SHA-256 `716ee4a677f4be0b89dcc0e89e3b6a09d0ae813b5fa3618de2433776a1f9cb33`.

For a completion edge subset F and vertex set U, d(U)=2|F internal to U|+|F crossing U|. Internal selected edges are at most e(U); crossing selected edges are at most both the available cut size and outside demand. Thus d(U)<=2e(U)+min(d(V\U),|delta(U)|) is necessary. The code computes this exactly for every two- and three-element positive-demand subset. Parallel edge instances increment multiplicities separately. Edges touching zero-demand vertices may safely be omitted because no completion can select them. Interruption propagates before any verdict; complete edge input is an explicit caller precondition, not something this pure helper establishes.

The current `near_quarter_model.orbit_map` excludes both diagonals for four-orbits, so quotient radius endpoints are distinct. A noncentral endpoint contributes one point to each of its reflected rows and consumes one quotient degree. A central endpoint contributes two central-row points, so its residual demand is (2-central_load)/2. This is precisely the existing `near_quarter_radius_graph.radius_obstruction` mapping. The selected diagonal pair consumes one unit in each of its noncentral rows before residual demands are computed.

Distinctness was checked against actual `near_quarter_rowbatch_core._scan`, `near_quarter_radius_graph.component_obstruction`, and reflection `diagonal_residual_checkpoint.residual_scan`. They implement orbit/row shortage, component parity and bipartite balance; the reflection scanner also counts global/component anti-diagonal colors. None implements subset edge capacity. The proposed five-vertex six-edge abstract example passes degree, parity and bipartite checks but gives d({a,b,c})=6>2+2. Assigning distinct edge colors also passes the older abstract color-count relaxation. This establishes logical distinctness, not reachability from a geometric prefix.

Independent `.venv/bin/python -m unittest tests.test_near_quarter_small_cut` passed all three tests in 0.037 seconds. These cover all three-vertex multigraphs with each multiplicity at most two and demands 0..2, all four-vertex simple graphs and demands 0..2, compared with independent exhaustive edge-subset degree feasibility; explicit parallel capacity and distinguishing cases; and interruption at every callback of passing/rejecting cases. No geometric wrapper or integrated search equivalence was tested. If later proposed, integration must use the full exact mask, preserve the frozen frontiers, and receive separate source/geometry review and measured cost assessment. The previous residual scan slowdown is reason to measure benefit, not evidence for or against this new predicate's performance.
