# Full-row unordered reflection-orbit batching

This is a tiny-only correctness experiment, not a production search or performance result. `research/diagonal_rowbatch_tiny.py` explicitly rejects n>5 and leaves the approved DFS, checkpoint, guard, queue and active workers unchanged.

Fix the deficient index d and the preinserted singleton `(t,t)`. At any valid partial state, choose one underfilled row deterministically. Its remaining capacity k is 1 or 2. An off-diagonal mirror orbit `{(i,j),(j,i)}` contributes exactly one point to each of rows i and j, so every valid completion must add exactly k distinct unselected incident orbits to that row. Every such orbit is individually admissible in the current state: occupancy, row/column capacities and collinearity constraints are monotone, so an orbit rejected now cannot occur in a valid extension. Enumerating every unordered k-subset of individually admissible incident orbits therefore includes the completion's exact batch. Insert each pair sequentially with transactional push; rejection of a batch means its union violates a monotone constraint. A valid full completion cannot be rejected by this test. No global orbit-order condition is used; sorting combinations only removes permutations within the same batch.

For uniqueness, two different candidate batches at the same node differ in at least one selected orbit touching the chosen row. After insertion that row is full, so no later extension can add another incident orbit. Consequently, completions reached through distinct batches at this first divergence differ. Applying this argument inductively to deterministic row selection yields one path per completion in a fixed `(d,t)` slice. A full invariant set has one diagonal singleton and one deficient row, so `(d,t)` is also unique for that set. Row choice affects traversal and work, not this proof, as long as all unordered admissible batches are considered.

The reference prototype selects the underfilled row with fewest individually admissible incident orbits, tie-breaking by row index, then enumerates `itertools.combinations` of size k. Every completed certificate is checked by both existing exact geometry verifiers. Two focused tests passed: for all n=3,4,5 deficit/singleton slices, the batch census contains no duplicate full set, equals the unique witness set from the reviewed fast DFS in each slice, and equals independent exhaustive tiny enumeration. The explicit n=3 `d!=t` fixture is reached. Counts from these tiny correctness cases: n=3 has 20 batch nodes and 4 witness visits versus 26/5 in original DFS; n=4 has 66/10 versus 108/17; n=5 has 205/16 versus 415/35. These counts demonstrate duplicate-path elimination on tiny instances; they do not predict runtime, memory, or larger-grid feasibility.
