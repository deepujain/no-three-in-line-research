# Independent immediate replay-domain reuse design review

The read-only design is sound, pending exact implementation and targeted tests. Reviewed proposal `research/near-quarter-replay-domain-reuse-proposal.md`, SHA-256 `3c122e2b220280bb0b35c32014825574f9fa9c58cf33f4aad9fe19407bc5d2c7`, against core `2f758f63...` and codec `46e5a2db...`. No source was changed and no host or numerical worker was launched by this review.

Structural parsing requires every interior frame to be WAITING. In `_restore`, the domain for that frame is reconstructed and checked against row, deficit, length, digest and current cursor. The next iteration currently reconstructs that same domain before checking the child's origin, exact incoming batch and successor relation. No selected geometry changes between those two reconstructions. Carrying the already validated immutable Domain directly to that next child-edge check therefore preserves the mathematical predicate and removes exact duplicate replay work.

Keep only the immediate previous domain; require it for each non-root frame and clear the carried reference before pushing the child. Preserve checks before reuse, during successor enumeration and throughout the actual child push, terminal/prune validation, external hashes, source checks and final adoption. Continue validating the current ancestor domain once, as well as child origin/batch/successor and parent-row coverage. There is no justification for broader cross-step traversal caching in this narrow design.

Implementation approval requires focused evidence that every tiny frontier phase has unchanged geometry, logical counters and control state; exact expected scan/probe reduction; malformed domain/origin/successor rejection; and interruption at every replay boundary without partial adoption. Existing save-validation faults must continue passing. Physical replay work should decrease while logical search is unchanged. Wall-time improvement and broad-grid allocation choices require actual bounded measurements. Root must release the current source identity before implementation; this design review is not an authorization to modify an active chain.
