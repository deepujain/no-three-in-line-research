# Row-block completed-boundary addendum: independent design review

Decision: PASS for implementation and synthetic review only, conditional on engineering memory/resource review. Reviewed `research/from-scratch-row-block-breakout75-boundary-addendum.md` SHA-256 `87312b2334325df68b1d4280f7321c910ae7bdd2ff97d8269a42d8dea2fa9ac0`; the original proposal remains unchanged. No search, actual geometry, checkpoint import or continuation was performed.

The proposed committed boundary consistently couples points, best state, scores, weights, RNG state, logical counters and stagnation. On interruption before positive-transition commit, discarding the provisional index/state and staged weight copy and restoring the pre-step RNG prevents a checkpoint from describing a partly sampled migration or a pending penalty. Attempted/aborted telemetry must remain separate from committed counters. Prechecking a whole penalty update and adopting a new immutable map only with the rest of the boundary prevents partial updates; tests must compare full state, RNG and weights at interruptions before and after random draws and during staging, including cap exhaustion. Temporary coexistence of two weight maps and two indexes is a real peak-memory cost requiring an owned synthetic envelope measurement.

A completed zero-score index gets priority immediately, including after a transition, before optional penalty or another search deadline check. If validator two starts before the 25-second deadline and accepts after it, the witness is saved immediately; if validator one finishes late, no second validation starts. The separately labeled raw zero checkpoint is not a validated witness. Any later pin or report failure must remain visible in receipt acceptance without deleting a saved witness.

A distinct, size-checked atomic checkpoint with a 2-MiB cap and the existing 1-MiB report cap keeps publication bounded, provided implementation enforces all stated numeric, record-count and metadata limits rather than relying only on estimated size. The 23-second search stop reserves finalization time but cannot guarantee soft-deadline completion or survive a hard kill; the 30-second/256-MiB owned guard and sampled-monitor limitations remain. No production resume API, automatic follow-on, or continuation allocation is authorized. A future reader must independently validate schema, source/runtime identity, state, score, weights and RNG before any separately approved use.
