# Three-exit, two-move census: design only

Status: design only. No implementation or n=79 neighbor scoring has been performed for this proposal. The initial one-neighborhood result and three exit identities must first pass independent actual audit, followed by independent mathematical and source/tiny reviews of this design and any implementation. A later actual run requires a separate lead-owned allocation.

## Question and inputs

The completed initial census reports all 12,560 attempts examined, with no score-5 or lower legal neighbor and exactly three score-6 neighbors: two column relocations and one uncolored rectangle. The initial state A has 157 points and exact score 5. These are execution findings pending independent actual audit, not newly computed claims in this design.

Once that audit is accepted, pin its exact bytes, the initial saved-state bytes and normalized identity, and a reviewed manifest of the three exact exit sets, scores, normalized identities and generating moves. The future implementation must recheck source and audit bytes, check every exit equals its declared legal move from A, verify pairwise distinctness, and independently dual-validate A and all three exit states, including exact conflict-coordinate agreement, 157-point cardinality and deficient-axis invariants. Each exit must have score 6 and a +1 move delta; no guessed coordinates or inferred identity suffice. Fail closed on any mismatch and recheck pinned inputs and implementation dependencies before publishing a receipt.

## Exhaustive bounded neighborhood

For each exit in stable manifest order, enumerate the same exact catalog as the accepted first census: 157 row-relocation attempts, 157 column-relocation attempts, then 12,246 unordered rectangle attempts, each with stable lexicographic point/pair ordering. Thus the complete three-parent enumeration contains 37,680 labeled attempts; invalid destinations and same-axis pairs are illegal and counted. Each legal move has exact integer delta, axis invariants and a verified reverse move returning the corresponding exit with opposite delta. No third move, recursive queue, automatic retry, continuation, descent, or temperature policy is included.

Preseed a global map with A and all three distinct exits, their scores and identities. Deduplicate resulting point sets by a canonical n*n-bit occupancy integer (bit index n*x+y), tracking each distinct candidate's first parent and whether it is A, an exit, or a novel state. An integer is bounded by 6,241 bits for n=79, with at most 37,684 map entries and constant-size metadata per entry; do not store full candidate point arrays or validators for every state. Report labeled attempts, legal/illegal and signed deltas per parent and move class; separately report the score histograms of novel unique states and all unique generated states, plus backtrack-to-A, exit-state, same-parent repeat and cross-parent revisit occurrence counts; these classifications can overlap. Track generated-seen and first generating parent separately even for preseeded entries. Each completed attempt is legal or illegal; each legal occurrence is either a novel first insertion or an occurrence of a preexisting map key, and map size equals four plus novel first insertions. Generated-unique histograms count each generated key once, including A or exits if reached; novel histograms exclude all four preseeded states. Validate a duplicate's computed score agrees with its first occurrence; otherwise fail. Pin exact algorithm/version and record the dictionary's count; the memory ceiling is enforced by the existing sampled outer guard, not inferred from this arithmetic. Report how many candidates are distinct and the exact counter equations; record first-seen score and parent with each compact key.

The main question is whether a state of score below 5 is reachable by exactly two of these moves from A with intermediate score 6. Any such end state has score at most 4, so the maximum score along the recorded two-move path is at most 6. Report all lower-score candidate identities or a bounded summary and a fully dual-verified best state with its exit and second move. An endpoint of score 5 is a plateau endpoint, not a strict improvement. Preserve each strictly lower best as soon as both independent validators agree on cardinality, axes, normalized hash, exact score, validity and canonical conflict triples. A valid witness must be atomically saved and stop immediately even when the soft deadline has elapsed during the second validator; it is a witness, not a proof of optimality or novelty. Positive-score saved states remain invalid. Ties retain the first in enumeration order. Do not treat a partial validator result as an exact candidate result or a witness. Do not retain all improvement identities in an unbounded list; the explicit maximum number of attempts also bounds optional emitted identity records.

## Completion, partial results and resource gate

One proposed gate uses one 25-second monotonic soft interval measured from process entry, inside the existing owned 30-second / sampled 256-MiB guard. The deadline covers input identity checks, verification and enumeration. Check time between attempts and before each expensive validator; a candidate fully validated by both is persisted even if the deadline passed during the second validator. Record started and completed attempts separately for each class and parent; an attempt is completed only when legality and any required inverse checks and bookkeeping complete. A validation timeout preserves earlier validated artifacts, reports timeout and incomplete, and never claims the partially verified candidate as an exact incumbent. Source mismatch, score mismatch, inverse mismatch, or duplicate-score mismatch is a failure with complete=false. Record guard and cleanup status separately; an outer termination cannot establish completion.

Complete negative evidence requires all 37,680 attempts, all legal inverse checks and any required best validations to finish, with no witness and no score below 5 found. It excludes only strictly improving endpoints of paths whose first move is one of these three score-6 exits and whose second move is in the specified catalog; the accepted complete initial census is required to infer that these exhaust all first moves with peak at most 6. It says nothing about longer paths, peak above 6, other moves, or global existence. At most four initial-state cells are removed across two moves, so any endpoint deletes at most five points of the fixed 158-point source. A zero-score endpoint would fall inside the earlier at-most-eight-deletion native UNSAT scope; that earlier solver result lacks an independently checked UNSAT proof, so any purported witness still requires both validators and investigation of the apparent contradiction. This census primarily characterizes the invalid-score barrier, not an independent new valid-construction region. A partial run reports only visited prefixes, and never claims the whole two-move neighborhood is exhausted. No repeated work on the initial neighborhood is required.

## Gate before implementation and run

Math review must check the catalog, count, classification, score claim and precise scope including the complete-first-census dependency. Independent source/tiny review must test against an independent determinant oracle for complete two-level neighborhoods on small boards; include backtrack, revisiting another parent, cross-parent duplicate, same-parent duplicate as a tested impossibility under the prior unique-neighbor proof, canonical bitset identity, class/count conservation, inverse deltas, mutation and malformed-parent rejection, timeouts at each parent and validator, immediate late-witness persistence, and guard lifecycle. Source, fixtures, math/source reviews, validators, guard, parent actual audit and output manifest must be hashed before any actual allocation. Choose one bounded gate; if it is incomplete, do not automatically run a second gate or change the scope.
