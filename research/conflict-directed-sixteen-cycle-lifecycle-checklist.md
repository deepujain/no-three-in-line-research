# Sixteen-cycle lifecycle review checklist

Scope: review of implementation only after author identifies frozen source and tests. Design reference `research/conflict-directed-sixteen-cycle-rebuild157-proposal.md`, SHA-256 `e08c066ae07885bcda24c7813ff1a0dc706d81bcfc267e4056ba8270a8279777`. Geometry, combinatorial completeness and independent tiny full-solution oracle are separately owned by the mathematical reviewer. No n79 input enumeration, score or search is authorized by this checklist.

- **One shared budget:** confirm monotonic start is captured at process entry, before all input reads and preparation, and propagated unchanged through each of at most eight patches; reject invalid budget values. Deadline checks occur during conflict-cover generation, padding, source/retained secant traversal, domain building, matching augmentation and certificate checking, and DFS propagation. Identify any noninterruptible operations and show that an outer guard covers them without claiming cooperative interruption.
- **One global insertion cap:** exactly 1,000 started replacement insertions shared across every patch, not reset on patch change. Increment before any insertion work; an interrupted insertion still consumes a start. No cap overrun or resumed patch, fallback family, altered configuration, automatic retry, or second gate. Test boundary 999/1000 with multiple synthetic patches and interruption within insertion.
- **Distinct lifecycle statuses:** verify started/completed counters and statuses for cover enumeration, padding, patches, root domains, matching/certificates, insertions and DFS. A timeout, error or cap cannot mark incomplete cover enumeration, patch, propagation, matching or search exhausted; completed zero-candidate scope is distinguished from incomplete. Once a full patch is correctly exhausted, its finding is restricted to that F. No all-family, global or UNSAT assertion on a sample of eight patches or a partial run.
- **Transactional rollback:** verify assigned arcs, row/column occupancy, used columns, point set and unsafe masks recover after rejected subtours, depth return, cap, injected deadline and exceptions in propagation and validators. Interrupted partial insertions must not leak state into later patches or final outputs. Failure must stop or explicitly mark error; no swallowed integrity exception.
- **Identities and source integrity:** hash-check S, A, the accepted independent audit and every dependency used by the fixed construction; compare normalized input identities, cardinality and exact five conflict-coordinate lists under both validators; require A subset S and one deleted S cell. Check parent path and source hashes again at report publication. Changed, missing, malformed, nonunique or unexpected input must fail closed. Review actual and test pin manifests without writing to frozen files.
- **Publication and correctness:** distinct new output paths, atomic replacement, no overwrite of inputs or prior artifacts. Save at most the first valid 156-point diagnostic, with axes, source distance and both agreeing validations; it is not a witness or lower-bound improvement. Do not publish partial validation or conflate failure with validity. At 157 explicitly verify degree pattern, F, replacement cells, single 16-cycle, source distance and both independent validators; immediately persist a dual-verified witness even if the soft deadline passes during the second validator, then stop all work. If time has expired before starting validator two, publish no unverified candidate. Investigate mismatch or publication exception rather than silently downgrade.
- **Fixed resource accounting:** verify arithmetic operation counters correspond to the design's stated unique cell visits, no duplicate line anchor visits, and expected per-phase caps; inspect actual memory structures for bounded eight patches, one active DFS stack and no unbounded candidate/visited cache. The outer 30-second / sampled 256-MiB guard is not a hard instantaneous RSS guarantee. Test guard nonzero, hard-stop and cleanup paths on tiny fixtures with no n79 selection.
- **Independent evidence:** run focused source/tiny and lifecycle tests on frozen hashes, plus meaningful fault injection for each partial phase, report filename/provenance, identity mutation and late witness/first diagnostic. Record exact tests, results, source/test hashes and limits in a separate review. Do not retest a historical source by modifying it, and do not confuse a source/tiny pass with actual host or n79 behavior.
