# Fixed-pool Boolean worker: native lifecycle review checklist

Review the frozen source and tests against accepted design `research/blocker-guided-fixed-pool-boolean-scaffold-design.md` SHA `9eb399607c16950ca19101a996dcccac05797aafc46980be8a68eb117ca2f5f9`. Mathematical semantic projection and complete tiny geometry oracle are owned by a separate reviewer. This checklist does not authorize n79 formula, solver, install or actual allocation.

- Identify the exact local native solver and checker binaries/libraries and versions, invocation, deterministic settings, proof/model format, license, and their hashes. Inspect source and supported options rather than assume proof support or compatible checker behavior. Missing/changed backend or checker fails closed; no download, package install or backend substitution. Verify hashes before invocation and final report, and pin the exact source/fixture/CNF/proof identities.
- The original 25-second monotonic interval starts at process entry, before preprocessing. A single SAT child has at most min(10 seconds, remaining minus 3 seconds), once only. Checker runs at most once after UNSAT and complete child cleanup, at most min(5 seconds, remaining minus 1 second). Deadline or nonpositive slice prohibits launch. Partial encoding, timeout, capped or unverified proof and checker failures never mark closure.
- Hard 64 KiB per stdout and stderr, 32 KiB parsed model and 8 MiB proof file; a child crossing any limit is stopped and the attempt marked incomplete/error. Demonstrate proof-file enforcement against native writes and child forks, not merely a Python buffer or polling claim; check partial-write, exact-boundary, signal and inherited descriptor cases. Distinguish file cap, stdout caps, checker logs, no output or malformed output; do not accept truncation as a model or proof. Make sure limits apply during spawn, process exit and cleanup.
- No daemon, new session or detached process group; child must inherit owned worker PGID and SID. Track native descendants, terminate only owned PIDs/group as appropriate, TERM grace <=0.1 seconds and additional KILL/reaping/descendant cleanup <=0.4 seconds. Reap and verify tracked descendant absence before checker launch. Test no child, timeout, fork/exited parent, uncooperative child, interrupted read and cleanup-failure cases on tiny native fixtures, excluding unrelated-process killing. Outer guard is sampled-RSS, not an instantaneous kernel guarantee.
- Accept a model only when exactly all declared variables occur once with valid signs/range and no contradictions, and evaluate every clause of the immutable exact emitted CNF before interpreting semantic variables. Link model to exact CNF digest and fixed pool identities. No second model/assumptions or repair loop. A SAT assignment is not a full witness; geometry validation and labels are checked separately by Math.
- On SAT, dual-validate decoded 149 set and immediately atomically save valid149 diagnostic before optional root work. If validator two completes after soft deadline, persist once; fresh deadline check prohibits starting root afterward. Root-ready149 is separate and never claims residual joint geometry or a 157 witness. A failed root does not invalidate the saved diagnostic or close other models.
- A raw UNSAT is unverified until an independently pinned checker accepts the exact CNF/proof bytes within its caps. Bind checker argv and accepted hash to those same bytes; reject invalid/truncated/proof-changed/mismatched CNF, incomplete checker, child cleanup failure, signals, timeouts or missing executable. Native solver status alone never grants closure. A checked proof closes only the exact fixed-pool 149 scaffold family.
- Tests: tiny SAT/UNSAT fixtures, malformed/missing/duplicate model entries, semantically false clauses, intentionally bad/truncated/wrong-formula proof, hard caps and overwrite/symlink cases, PID/session lifecycle and descendant cleanup, timeout at each boundary, mutated pins, validator disagreement, diagnostic/witness atomic failure and late dual-save. Keep source-independent geometric enumeration separate; record exact commands, hashes, platform, output, and sandbox restrictions. Any actual n79 execution requires separate source/tiny review and lead allocation.
