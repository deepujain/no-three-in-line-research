# Reusable exact depth-12 continuation: mathematical design and execution contract

Decision: PASS for a new single-chunk depth-12-only implementation, followed by independent source/tiny review. Preserve `research/near_quarter_depth12_cut_continuation.py` SHA-256 `797de26c12bcf09a6e9d1ce017c49e200bfa55f6a0dc9b6677d282cca7c55bdc`. This design review performed only source/artifact identity reads and mathematical reasoning; no n=79 search, formula construction, geometry evaluation or solver replay.

The simplest reusable interface executes exactly one explicitly requested chunk and accepts a seed report path plus its explicit expected SHA-256, and the completed owned receipt path plus its explicit expected SHA-256. The caller supplies a fresh output directory. The implementation never launches, schedules or retries another chunk. Root controls at most two sequential, separately reserved 25-second soft / 30-second owned / 256-MiB chunks. This separation avoids a new adapter per chunk while keeping allocation outside the search source.

## One chunk and the two-chunk owner rule

Each invocation has one absolute soft deadline beginning before seed loading and validation, with only remaining time passed to its native interrupt timer. Seed/hash validation, mask reconstruction, formula building and native work are inside this budget. Timer cancellation and join precede solver deletion. After both full validators already agree on a valid witness, save it immediately even if the soft deadline elapsed. The owned guard bounds that validation/publication tail. Immutable input and source rereads precede final atomic report publication. Seed artifacts and accepted chains are read-only.

Root may reserve and execute chunk 2 only after chunk 1 has returned, its owned process group is clean, and its completed receipt is durably saved. Chunk 1 must have status timeout or solver_unknown, have added at least one new distinct valid cut, and have total cuts less than 1000. Bind chunk 2 to the exact hashes of chunk 1's report and completed receipt. Native UNSAT, witness, cut_limit, integrity error, hard-guard failure, incomplete receipt, no cut progress or any other stop disallows chunk 2. There is no third chunk, automatic retry, depth extension or capacity widening in this design. No search source loop is needed to enforce the owner allocation rule.

The owner checks receipt provenance and clean termination separately from mathematical constraint acceptance. The seed loader should verify that the supplied completed receipt identifies the seed report's execution/output and expected source pins, and reject altered sources or incomplete/inconsistent receipts. A timeout/unknown status is only the owner scheduling condition; it is not evidence that a clause is valid or that the prefix is satisfiable. Model counts need not equal newly saved cuts if timeout occurs during model validation.

Loading all constraints and validating them locally allows a second bounded search before an independent full audit of chunk 1, provided the owner gate above passes. It does not promote chunk 1's execution-history or solver claims. Independently audit completed saved results before promoting their status, constraints or any claimed witness. A native negative remains conditional exact-prefix solver-reported UNSAT unless a separate proof is checked. No global board conclusion follows.

## Implementation and tiny-review requirements

Use a new source, keep frozen sources unchanged and pin its dependencies and fixed evidence. Resource handling must fail closed on malformed files and counts. A simple bounded seed-file read is sensible: the current seed report is 128063 bytes and receipt 10158 bytes, so a documented generous finite limit can avoid unexpectedly large JSON allocations. Fixed base-audit bytes are known and pinned (9234721 bytes); account for their parse memory under the same owned 256-MiB gate rather than presuming the prior peak is a guarantee. Do not retain redundant full copies when only cut IDs are needed.

Tiny tests must cover dynamic pinned seed selection, wrong report/receipt hash or provenance, exact prefix/map/mask and binary identity, all malformed/duplicate ternary cases, altered initial 487-cut anchor identity through synthetic equivalents, retained/new/total accounting, a second synthetic continuation preserving every first-run cut, zero remaining allowance, violation of old/new clauses, no pair reprobe or extra depth, one deadline, native unknown/timeout/UNSAT/witness/cap/error outcomes, timer cleanup, late valid witness saving and source/input mutation before publication. Use tiny or mocked geometry only; 487/1000 and 513 are arithmetic bounds. Independent source/tiny review precedes Root's numerical allocation.
