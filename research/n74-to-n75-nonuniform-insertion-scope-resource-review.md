# Nonuniform n=74 to n=75 insertion: scope and resource design review

Decision: PASS for source implementation and synthetic review only, not an actual source import or numerical allocation. Reviewed design `research/n74-to-n75-nonuniform-insertion-design.md` SHA-256 `ef586abba0cf54918cb83040e9221fca48e8f578fc35fad0c60d693a31167605`. Independent geometry review remains necessary.

The proposed 5,621 choices exclude the four cases with both gap coordinates at boundaries. Interior insertion changes some old coordinates and their Euclidean collinearities. The available public report of testing free cells against one fixed n=74 embedding does not itself test those changed old geometries. It also does not identify its precise source record, so neither complete independence from all prior work nor novelty follows. The exact selected n=74 archive record, source bytes, normalized identity and two independent validations must be established before any geometry-dependent shortcut or actual pilot; a source-specific prior result may require curtailment. No construction, lower-bound improvement, or global priority is inferred from this design.

The design states finite ceilings for original triples, rectangle tests, pair-line work and stored obstruction records, and correctly distinguishes a complete obstruction cover from a full score census. Its bit-mask precomputation and per-rectangle bounded big-integer operations still require real storage and CPU accounting: the estimated logical payload omits interpreter overhead and is not a timing guarantee. Any implementation needs deadline checks during precomputation, both geometry classes, certificate extraction, source pinning and final publication, plus the unchanged owned 30-second/256-MiB guard for a separately authorized 25-second cooperative pilot. An interrupted cover with uncovered gaps cannot certify either impossibility or a valid candidate.

Before allocation, require tiny independent full-target determinant comparisons across both triple classes, mask and signed-clipping edge cases, exclusion of the four boundary cases, sound early-complete certificate validation, and proof that a late valid witness is saved before optional work while final identity/deadline failure clears completion and closure. The source must be independently validated before skipping uniform translations. Resource acceptance must account for actual process memory, certificate representation, I/O and guard cleanup; estimates alone do not establish host feasibility. Negative closure would apply only to the exact selected source and stated gap family, and no automatic fallback is justified.
