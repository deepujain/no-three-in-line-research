## Complete bounded scratch scan

Validate strict integer n in 2..79 before grid-dependent allocation. At a coherent state compute `b_r = target_r - rows_r`; every value must be 0, 1 or 2 and the total demand must be even. Invalid arithmetic is an invariant failure, not a prune. If all demands vanish, return the existing full-state sentinel; the unchanged leaf path then checks cardinality, reflection, axes and both exact geometry validators.

For a nonfull state, scan the canonical orbit list exactly once. For each unselected orbit {x,y}, evaluate the frozen exact admissibility predicate against the unchanged prefix and its complete occupied-sum set. Store an admissibility byte by orbit index, neighbor row bitsets, per-row degrees and a global x+y color bitset. Only positive-demand vertices may have edges. Keep every positive-demand vertex in the graph traversal even when its degree is zero. Canonical one-pass construction deduplicates edges automatically; no partial graph, sampled candidates, shortened orbit domain or stale cache is allowed.

After the full edge scan finishes, check all degree shortages. Traverse connected components in ascending root/neighbor order, assign bipartition colors, collect demand and side-demand totals, and test component parity and bipartite balance only where applicable. Detecting an odd cycle disables the side-balance test for that component; it is not itself a failure. Accumulate component x+y color bitsets from the complete admissibility vector, then test the global and component color capacities. Rule-hit diagnostics may overlap. A rejection returns an empty candidate list for this coherent node.

For a passing state choose exactly the old MRV row `(degree, row_index)`. Rebuild that row's viable orbit IDs in the unchanged canonical order and materialize the same lexicographic singleton/pair combinations as the old core. This preserves the existing cursor interpretation within the new source identity. No forced-edge propagation, candidate reordering, all-pairs conflict graph or exact factor/matching solver is introduced.

At n79 the graph has at most 79 vertices, 3081 possible edges, 155 possible sums and 79 component IDs. Admissibility needs 3081 bytes; neighbor bitsets and colors have bounded Python integer sizes. The chosen row has at most 78 IDs and at most `C(78,2)=3003` batches. The inherited per-depth option lists remain as in the reviewed core; this design does not claim their Python memory cost equals packed arithmetic. Import, Python objects, tuples, verifier allocations and the full owned process tree still require actual RSS measurement. Nothing is retained as a global search-history cache.

## Interruption, replay and counters

One monotonic invocation clock accounts for reconstruction, scans, traversal and final publication. Cooperative deadline checks occur at the inherited work boundaries and the new graph boundaries: before/after the edge scan, during every orbit iteration, component/neighbor pass, color accumulation and candidate-combination iteration, and immediately before returning a verdict. The inherited final encoding, source reads and atomic checkpoint write are not cooperatively interruptible by that deadline. The outer guard measures the overall elapsed interval, rejects a late result and clears acceptance after a late publication; bytes already published can remain explicitly unaccepted. Neither this design nor that corrective rejection promises a hard real-time limit for filesystem operations or their final cleanup tail. Graph code never mutates geometry or committed frontier/counters. A check that raises cannot return a partial rejection, candidate list or leaf.

The reviewed candidate-call sites catch timeout before incrementing the current node's count or installing its next cursor. New computation is scratch until complete. During resume, deterministic scans are rerun for each saved ancestor and its child/cursor relationship. A pruned ancestor cannot legitimately have a live child under this same frozen identity. Invalid replay fails; a timeout while reconstructing an existing accepted frontier returns the original unchanged bytes/hash and zero new logical nodes, and the guard classifies it as reconstruction timeout with no new promotion. Initial genesis timeout may publish only the existing unentered-genesis representation under its new identity. No new acceptance is inferred from an unchanged checkpoint.

Preserve exact cumulative node/witness and per-slice counters. Pruning changes the tree and therefore its counts, but not counter definitions. For cost diagnosis add only per-invocation physical work to the worker report: edge tests, graph passes and overlapping named rule hits, separately attributed to reconstruction versus newly visited states. Do not serialize those measurements as historical tree counters or add callbacks inside secant mutations. Bound physical counters and fail on overflow. Record reconstruction/new-work durations, and continue reporting the total guarded interval; phase subtotals are not substitutes for the helper's whole-tree acceptance record.

## Separately scheduled measured host gates

All launches and receipt acceptance remain with the Lead. These are proposed gates, not execution authorization. Reuse the unchanged helper with at most 30 seconds and 256 MiB sampled RSS, including cleanup, and fail closed on monitor/source/signal errors. No automatic retry, fallback or cap increase follows failure.

1. After source approval, actual-host n3/n5 initial/save/resume runs under a 10-second/256-MiB guard must match the tiny witnesses/counters, preserve externally pinned predecessor links and report positive RSS samples and clean cleanup. A separate SIGTERM case observes a worker before cancellation, then requires rejected promotion, clean owned cleanup and the recorded worker's disappearance. Injected tiny clocks prove phase-specific graph interruption; simply observing a worker does not prove the host signal landed in a graph pass.
2. A separately reviewed no-search test worker can build an n9 root in one declared slice, run exactly one complete residual scan, compare its verdict/candidate order with the frozen control when the verdict passes, and exit. It records source identity, exact prefix description, work, total wall/RSS and cleanup under a 10-second/256-MiB gate. A separate n9 one-node initial/resume pair tests the complete publication path if this preflight passes.
3. Only after reviewed smaller gates and explicit scheduling, run the same root-only scan at n79 with no DFS, checkpoint continuation or claimed search coverage, under a 30-second/256-MiB gate. Use declared (0,0); a separately allocated (0,1) root preflight preserves an exploration hypothesis. The guard measures orbit/state construction, complete scans, verification and report overhead. A passing root-only scan establishes only that measured operation, not deep-prefix reconstruction cost or a memory bound for a full frontier.
4. A subsequent fresh-genesis n79 cost stage, if authorized after review, is limited to at most 100 new nodes, the fixed 30-second/256-MiB gate and one exact declared slice. A resume stage requires its own accepted digest and allocation. Report committed nodes, physical scan/prune work, reconstruction cost, accepted bytes/hash and resource samples. A node reduction relative to another implementation's different frontier is not a controlled throughput comparison. A production chain or larger allocation needs separate review of these observations.

The frozen reflection control and at least one separately allocated exploration slice remain available. The open hypothesis is useful larger-prefix rejection at acceptable scan cost; no wall-time advantage, witness existence, novelty or family exhaustion is asserted by this design.
