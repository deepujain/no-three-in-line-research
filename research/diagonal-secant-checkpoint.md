# Checkpointable fast diagonal DFS

This separate prototype uses the reviewed fast DFS's state and mirror predicate without changing the frozen fast core, guards or shared adapter. It serializes a single iterative DFS stack per active `(deficit, diagonal)` slice: each entered frame stores its selected orbit and the next candidate index, and its pending child is represented by an unentered frame. The stack plus later slice indices represents the remaining DFS traversal without materializing an exponential set of subtrees. Reconstructing each frame recomputes the same MRV candidates and validates each parent/child cursor and insertion. Full exhaustion is reported only after all declared slices and stack frames are consumed, and is restricted to the diagonal-reflection family.

The checkpoint records the grid, complete ordered slice selections, exact orbit-order hash, explicit branch-order version, implementation and verifier hashes, cumulative node/witness counts, and per-slice counters. Resume requires the caller to provide the expected hash of the exact previous checkpoint; it rejects missing, changed or wrong-identity data. The path is not part of identity, so exact checkpoint bytes can be relocated. A checkpoint hash is an external trust anchor, not authentication: a party able to substitute bytes and the expected hash can forge state. One exclusive owner per checkpoint is required; the check-before-replace is not a concurrent-writer lock.

A bounded invocation publishes one checkpoint atomically after traversal stops. Before replacement, a crash or callback failure leaves the previous frontier intact and replays the uncommitted portion on resume; witnesses must be saved atomically and idempotently. After replacement, a lost return value leaves a new checkpoint whose `previous_checkpoint_sha256` records the preceding expected hash. Recovery requires inspecting and accepting that locally trusted new checkpoint and pinning its actual digest; an old digest is rejected. The file is fsynced before replace, but the containing directory is not fsynced, so this is not a power-loss durability guarantee. The standalone CLI writes dual-verified certificates atomically by normalized geometry hash. A callback may repeat across failed invocations, and witness visits include alternate insertion orders.

The time deadline is cooperative and checked on entry and during candidate enumeration; restoration, a single push, geometry verification, callback and checkpoint I/O can overrun it. Timeout is never reported as exhaustion. An external resource guard and independent review are required before scheduling; none is integrated here.

Five focused tests plus the two fast DFS equivalence tests pass. For n=3,4,5, three-node slices reproduce the unsliced search's full ordered witness visits, per-slice counts and node totals. Tests cover hash and identity mismatch, relocation, malformed state, timeout, changed sources, failed callbacks, and interruption immediately before and after atomic replacement. No n=79 run, benchmark, queue edit or shared adapter change was made.
