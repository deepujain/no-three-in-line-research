Two corrections were required and reviewed.

1. Retain the lease for every uncertain HEAD attempt, including cleanup exceptions. In `_commit_head`, an error after `attempted=True` ordinarily returns `acceptance_uncertain`, but its `finally` descriptor/temp cleanup can itself raise and override that return. `run_stage` only changes its currently false `retain` flag after `_commit_head` returns normally. An attempted replacement followed by failure unlinking the remaining `.head-*` temp therefore escapes through `run_stage`'s exception path and releases the lease. Make the retention decision conservative before any potentially uncertain commit call, or ensure all post-attempt cleanup failures preserve and return the uncertain state. Add a regression case combining replacement failure with temporary cleanup failure; assert that the lease remains and a retry cannot launch.

2. Do not claim complete physical counters after interrupted private save replay. Worker `complete=True` records successful initial construction/restore. A subsequent `save_candidate` invokes a private replay; its work only reaches `core.validation_work` after that replay returns. If a deadline or error interrupts this private replay, the partial work is unavailable but the failure report currently retains `physical_counters_complete=True` and exact-looking `validation_extra`/`physical_total`. Mark physical accounting incomplete/null unless partial clone work is available. Test a stop after positive replay work and require rejection with unknown counters, no checkpoint acceptance and no save-budget bypass. Logical accepted-parent counters are unaffected.
