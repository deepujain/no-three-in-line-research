## Four-row hypothesis: no defensible fixed instance

The four-row overlap hypothesis remains `research/four-row-overlap-exploration-design.md`, SHA-256 `d7c7bcb8c53febfba3eeeb68d93894ecc5c60fb697a58c491bd3170aa1f4c8c7`. I cannot currently justify one predetermined real-grid n5..8 row-valid state and four-row block with a credible separating mechanism, without searching or evaluating candidate fixtures. I therefore propose **zero fixtures** and no oracle run. Giving arbitrary coordinates merely because they contain overlapping conflict triples would not explain why all three-active faces should fail; dense symmetric collinearity constructions commonly expose immediate smaller-support repairs. The abstract four-bit cycle energy in the earlier memo does not supply a legal grid embedding.

The eventual falsification requirements remain strict. A single immutable input must specify all points, n, one four-row block and common current-inclusive domains before any executable evaluation. The block must be the union of two current K-positive row triples sharing exactly two rows. On that same input and those same domains, direct exact scoring must show a strict full four-row gain while **each** of the four faces holding one selected row at its complete current assignment has minimum equal to the current score. Every legal singleton orientation consistent with the face must be included. These inequalities imply that every strict improvement in that common domain changes all four rows.

An additional, different comparator must show that **every** eligible K-positive triple in the original production family, with its own original retained-only-unary four-column domains and all legal loads, has minimum equal to the current score. A face improvement, a production-family improvement, a block outside the overlap selector, no four-row gain, wrong current inclusion, score/tie disagreement or an interrupted accounting budget rejects the proposed separating evidence. A selected four-row improvement changing fewer rows, a domain change alone or an abstract energy example cannot pass. No failure authorizes another instance or wider domains. Nothing here asserts that such a separator exists or that the actual64 state has this barrier.

That report supplies no four-row fixture, local-minimum theorem or permission for a third chunk. Independent actual acceptance remains separate. ## Alternative: domains preserving a best one-row repair

The original domain ranks missing columns by conflicts against pairs of retained points after removing all three selected rows. It omits conflicts involving current points in the other two removed rows from that ranking, although the exact block objective later includes them. Therefore this unary ranking has no general guarantee that it retains a strictly improving same-load one-row replacement. This is a limitation of a domain-selection certificate, not a demonstrated cause of the actual64 result.

A different deterministic domain rule has an existence-preservation theorem without increasing the four-column cap. For each row r in a fixed row-valid state P, let A_r be its current column set and k_r its current load (one or two). Hold every other row fixed. Among **all** k_r-subsets of the n columns, choose B_r minimizing the exact full raw score of the resulting state, breaking ties by the increasing column tuple. The current A_r is a legal candidate. Define the seed domain A_r union B_r. For a full row its size is at most4; for a singleton row it is at most2. Fill to min(4,n) columns by increasing column number among the missing columns. This deterministic filler introduces no further score oracle and always preserves the current assignment. B_r is computed once against the full current complement, not separately against a different complement for each selected triple.

This is a design mechanism, not an implementation proposal for the actual input. Full exact row-placement scoring may cost much more than the old retained-only ranking. The theorem does not claim that every arbitrary improving replacement survives, that B_r is unique without its tie rule, or that domains contain all old production domains.

**Existence-preservation theorem.** If some row admits a strict replacement preserving its current load, then B_r is strict, and there exists a current K-positive three-row block in which assigning B_r to that row and leaving the other two rows unchanged is feasible in the new domains and strictly improves the full raw score.

Proof:

1. B_r minimizes a set containing every proposed same-load replacement. If any such replacement improves, the minimizing B_r improves too. If none improves, this argument promises no gain.
2. A strict replacement must remove at least one old conflicting triple containing a point of row r. Otherwise the old triples involving that row contribute zero, all triples avoiding it stay unchanged, and the replacement can only add a nonnegative number of conflicts. Strict decrease would be impossible.
3. In a row-valid state with at most two points per row, a conflicting triple cannot use two points from the same row: their horizontal line meets no point in another row, and a third point in that row is absent. Thus the removed conflict occupies three distinct rows r,s,t and makes their current K_rst positive.
4. Select that existing eligible triple. Its domains contain B_r in row r and the complete current column sets in rows s and t. Preserve the current per-row loads, hence also the selected total load5 or6 and the unique-singleton structure. The assignment is legal under the block orientations. Its full point set equals the same-load one-row replacement, so its exact block score is the same strict improvement.

Consequently, exhaustively finding no gain over all K-positive triples under these new domains would exclude strict **same-load one-row** replacements. It would not exclude arbitrary three-row replacements, changing the singleton row, untested states or unrestricted minima. The theorem asserts that an improving option is feasible in some eligible block; a finite prefix may never visit that block, and an optimizer could choose a different improvement there. It establishes no necessity of three-row coordination. It is a domain/selection-route guarantee and could instead support a separate diagnostic certificate; it grants no reason to resume or rename the curtailed algorithm.

## Conditional one-input oracle contract, not an allocation

No input for this alternative is ready. Before any future SOURCE/TINY test, freeze exactly one independently reviewed n5..8 row-valid point array (2n-1 distinct in-grid cells, one singleton row and two points in every other row), its canonical byte/hash identity, the purpose of the instance and all tie/fill rules above. No seed list, transformed copies, candidate generator, actual64 subset, second instance or adaptation after seeing scores is allowed. Without that fixed input, this remains a proof and test design only.

On such a future fixed input, a basic oracle can score the baseline and all same-load row placements. At n8 there are at most7*C(8,2)+8 =204 placements, including current placements, hence205 scored states including the baseline. Record each row's lexical minimizing B_r. A baseline direct determinant census also records all current K-positive triples. For each strict row winner, choose the lexically first current conflict triple containing that row; check its domain containment, legal unchanged-other-row assignment, full point identity and direct score equality. At most eight embedded assignments require a further score, so at most213 scores cover this existence test. It tests one predetermined state, not a fixture search.

Every scored state has at most15 points, so a direct raw oracle needs at most C(15,3)=455 determinant tests. The basic existence test therefore has at most96,915 raw-score determinants. An independent canonical-integer-line oracle can rebuild at most C(15,2)=105 line keys per scored state and sum C(multiplicity,3), at most22,365 pair-line constructions. Use exact integer coordinates and rational/integer-normalized lines, with no floating-point tolerance. Check canonical point identity, row loads, current inclusion, lexical ties and equality of the two raw counts. These are operation ceilings, not timing or physical-memory forecasts.

Demonstrating a **new domain-route witness**, rather than only validating the theorem on a state that already improves, would additionally require every original production K-positive three-row neighborhood to fail on the same frozen input. For n<=8, at most C(8,3)=56 triples and432 assignments per triple give24,192 additional states. This includes both legal selected totals: total6 forces2/2/2, while total5 includes every1/2/2 orientation. Computing original missing-column unary costs directly uses at most56*3*8*C(10,2)=60,480 further determinant tests. Together with the basic213 states, the complete comparator design has at most24,405 scored states,11,164,755 determinant tests including those unary costs, and2,562,525 pair-line constructions. A later implementation must keep explicit stop-before-increment caps of12,000,000 determinants and2,600,000 pair-line constructions; no numerical reservation is made here.

For that stronger witness, require at least one strict B_r and equality of current score with the exact minimum of **every** original production block. If the original policy already improves, report that the input does not demonstrate a new domain route. If no strict same-load row winner exists, report that this input supplies no positive mechanism witness. Score/identity/tie/domain/accounting failure rejects the test. A negative, incomplete or inconclusive result ends that one-case evidence proposal without selecting another input. Even a positive tiny domain witness would justify only a new design review, not actual64 execution, cap growth, a third chunk or a four-row necessity claim.

This alternative has a precise mathematical guarantee but currently no selected demonstration fixture and no evidence of benefit on the actual state. The honest result of the bounded exploration is therefore: no four-row fixture or oracle allocation is ready; a different domain-certificate mechanism is mathematically specified for review, with any future one-input experiment separately frozen and authorized.
