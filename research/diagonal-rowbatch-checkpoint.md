# Checkpointable diagonal row-batch core

This separate core implements the independently reviewed full-row batching rule. It does not modify or adopt the older single-orbit checkpoint format; both are separate search traversals and old frontiers remain unchanged. No guard, dispatcher or n=79 execution is included. Independent core review, guarded integration, tiny host gates and a separate allocation are required before larger use.

Identity format `diagonal-rowbatch-frontier-v1` binds n, the sorted complete declared `(deficit, diagonal)` slice lists, source hashes for this core, the tiny reference, checkpoint utilities, original and fast DFS cores and verifier, the exact reflection-orbit ordering hash, and `minimum-viable-row-then-lexicographic-unordered-batch-v1`. Each slice starts with its singleton inserted. Row choice minimizes the number of individually admissible incident orbits, tie-breaking by index; its remaining load k is one or two. The branch candidates are all lexicographically ordered k-combinations of those orbits. Sequential transactional insertion checks compatibility within each batch; a rejected batch rolls back every successfully inserted orbit and is skipped. The correctness and unique-path proof are in `diagonal-rowbatch-tiny.md`.

The frontier contains the slice index, cumulative and per-slice node/witness counters, and an iterative stack. The root frame has `batch=null`. Every child frame stores its chosen sorted orbit-index batch and a `next` cursor. A `next=null` frame is a pending, unentered node at the top of the stack; an integer cursor marks an entered node and the next unordered batch to try. A parent cursor is incremented before an accepted child frame is pushed, so restoration requires the child's batch to equal the parent's preceding candidate; rejected batches advance the cursor but never create a frame or consume a node. Restore reconstructs each deterministic candidate list, revalidates cursor and batch identity, and replays each batch with exact state insertion. Per-node candidate lists are at most quadratic in n and the stack is bounded by the number of orbits inserted; this does not materialize the exponential search tree.

Each invocation counts only newly entered nodes, stops at a node quota or cooperative deadline, and atomically replaces the frontier with its new bytes and preceding checkpoint SHA. Resume requires an externally trusted exact SHA and the same full identity; the path may be relocated. The caller must provide exclusive ownership. Atomic replace and fsync of the file do not prove directory-level power-loss durability; the containing directory is not fsynced. A failure before frontier publication replays work on resume, so callbacks must be idempotent. The CLI atomically writes hash-named, dual-verified witnesses before publishing the frontier. If a crash occurs after replacement but before its return, the old hash is rejected; recovery requires explicit review of the trusted new file and predecessor, not simply adopting an arbitrary computed hash. A checkpoint hash is not authentication if an untrusted party controls both checkpoint and supplied digest.

The deadline is cooperative, including checks during restoration, row/candidate scans, individual combination materialization and between batches. An individual push, witness checking/callback and file operations can overrun it. If reconstruction times out on resume, the trusted checkpoint bytes and digest are preserved with zero new nodes; a new invocation that times out during initial reconstruction publishes only the unentered initial frontier. Input supports n=2..79, reads at most 1,000,001 bytes and rejects checkpoints over 1,000,000 bytes, at most n stack frames, and at most n indices per slice axis. Completion is reported only when all declared slices are exhausted and is restricted to this reflection family; an external resource guard is still required for wall/RSS enforcement.

Six focused tests passed. For every n=3,4,5 slice and node quotas 1, 2 and 5, resumed searches match the tiny reference's exact ordered visits and per-slice node/witness counts, with no duplicate full sets. Tests also cover invalid hash/configuration, old-format rejection, relocation, time cutoff, source change, atomic interruption before/after replacement, callback failure and dual witness validation. A standalone n=3 CLI test of the earlier revision stopped after one node and resumed to all nine slices at 20 total nodes and four visits; the revised core is covered by the sliced tiny tests. No large model or benchmark ran.
