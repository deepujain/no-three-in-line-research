## Projection and geometry

The bidirectional q and d definitions are necessary. If only x->d is imposed, a model can set a deletion bit for an old conflict point that is not a selected support, satisfying an old conflict clause while that point remains in A minus F. If only x->q is imposed, a solver can set an unsupported q true independently of selected arcs; q no longer has exact planted-cell semantics or a unique extension. Here every q occurs only negatively in geometric clauses, so an extra true q adds restrictions and omitting this reverse implication alone does not produce a false-positive scaffold-existence result when decoding Q from selected x. Setting an unsupported q false is harmless and correct. Reverse OR clauses restore exact semantics; a zero-support point gets a negative unit. In a tiny abstract fixture with one unrelated selected arc and an old triple (a,b,c), setting d_a=true despite no selected support at a demonstrates the first false projection; the reverse implication forbids it. This is a local clause counterexample, not a claim that the fixture is a complete realizable board.

Exactly eight selected arcs plus pairwise disjoint endpoint row sets and column sets imply sixteen distinct old support cells forming a matching. Two different arcs for one q necessarily share its row and column, so at most one is selected; the q equivalence then yields exactly eight distinct q cells. The d equivalence yields exactly the sixteen selected support cells, no extras. Because q cells are outside S and A=S minus one, the reconstructed P has 141 retained source cells, eight outside-source points, 149 total and D17. Any endpoint row/column collision, even between distinct old points, invalidates the matching; testing only identical endpoints is insufficient.

Every triple in P contains zero, one, two or three members of Q. The four clause groups cover these cases respectively: hit every old conflict; hit every old pair collinear with each selected q; delete each old point collinear with each selected q pair; forbid every collinear selected q triple. They are sufficient and necessary when original conflicts, direction-bucket pairs and pair-table masks are complete and use distinct points. q outside S ensures q and retained A do not coincide. An incomplete or stale pair-table reconstruction can silently omit a clause, so exact canonical hashes, direct output validation and mismatch-as-error are essential.

A conceptual example illustrates why each new-point class is distinct: old blockers alone cannot reject a triple consisting of two selected new points and one retained old point, and the two-new clauses cannot reject three collinear new points. Tests should remove each group in a test-only encoding and produce an explicit semantic counterexample, not simply test that clauses exist. Compare projected assignments with independent determinant enumeration on small actual coordinate/support fixtures, including a line with four old points, source overlaps, same-F/different-Q, and arc pairs sharing a row or column but no old endpoint.

## Cardinality and assignment identity

The stated four threshold clauses encode z iff a OR (x AND b): the first two force z when a or x AND b holds; the last two force a OR x and a OR b when z holds, jointly giving a OR (x AND b). Base constants inductively fix each z for every x assignment, so asserting threshold8 and not threshold9 is exactly eight and the counter adds no independent assignments. At n inputs, this reasoning depends on retaining both reverse clauses after correct constant simplification; exhaustive tiny truth tables and auxiliary-uniqueness tests are required.

If F is a matching, each planted cell q has exactly one F edge on its row and one on its column, so F and Q determine its support arc uniquely. Therefore permutation order does not generate distinct semantic assignments, and the full-equivalence auxiliaries likewise add no extra models. Different Q sharing F remain different assignments. This is a mathematical property of the complete encoded catalog, not a measured solver speedup.

## Claims and failure boundaries

A valid decoded model is an exact fixed-pool 149-point scaffold only after independent set/axis/distance checks and both full validators. It is not automatically root-ready: the residual matching may fail, the allowed residual graph may lack a single 8-cycle, or the eight planned cells may be individually safe but jointly collinear. The revised design saves a fully dual-verified 149 diagnostic immediately, then checks the deadline before starting optional root work; a failed or unfinished residual gate does not invalidate that saved scaffold. One failed residual gate on the first model says nothing about readiness of another model. This one-model design must not add a blocking clause, make a second solve call, or describe that failure as a fixed-pool readiness obstruction.

Proof-checked UNSAT of the exact immutable CNF would exclude all eight-arc scaffolds in this particular audited 64-cell/246-arc catalog if and only if reconstruction and encoding were complete. Raw solver UNSAT, unsupported or truncated proof, timed-out encoding/checker and model/geometry disagreement are not closure. Nor would such a proof exclude scaffolds outside the fixed pool, different deletion/move structures, or all D17 completions. The previous retention SAT concerned direct target157 with effective-source deletion constraints; this model instead selects a restricted 149-point scaffold and support structure at exact D17. The earlier D9..12 run timed out, and its result is not an exclusion; neither formulation is being relabeled as the other.

The independent tiny gate should exhaust all small support subsets and compare precisely the semantic projected set with a direct geometry-and-axis oracle; verify q/d and threshold auxiliaries have unique values; and challenge missing reverse implications and each distinct triple class. Test model rejection, checked versus unverified UNSAT, exact formula/proof binding, pin mutation, incomplete preprocessing, first-model residual failure and late artifact persistence. The proposed SAT backend, proof verifier, resource accounting and actual allocation remain separately owned and unverified here. No result in this review asserts an n79 scaffold, solver speed or a novel construction.
