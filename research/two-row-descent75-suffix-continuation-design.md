## What the existing boundary can preserve

Every coverage cursor belongs to an exact state identity and ranking-policy identity. At entry use generation28, phase `pair`, completed pair prefix32, no pending optimizer and a carried completed row sweep. A pair is identified by `(state_normalized_sha256,r,s)`. Repeating the same row labels after a strict state change is a different neighborhood; skipping the old labels on a new state would be unsound.

Before each optimization increment its cumulative started count and durably write the selected ordered-list index as pending; the optimizer begins only after that bounded write succeeds. Remaining204 row starts add at most2249304 line visits and566100 choices. At most65 further strict moves bound accepted-state reconstruction to at most66 complete index builds, with at most one pending interrupted build. The first pilot's4.37 seconds,55-MiB sampled RSS and32 completed pairs make a64-start suffix a reasonable limited experiment; they do not predict a hard runtime bound. Retained-line and partner iteration ceilings are fixed, but different load orientations, new states, validation, machine conditions and cursor I/O can alter cost. Require new SOURCE/TINY split-boundary/cursor and worst-envelope tests plus independent mathematical/lifecycle review before any allocation. Keep the same25soft interval with23search/2shutdown reserve and30owned/256MiB guard. Never expand the cap to consume leftover wall time. If the gate cannot finish its cap, preserve the completed prefix and report a scoped partial result without automatic restart.

The first32 pairs failed despite ordering by largest removed triple incidence M. This is evidence of a plateau in the most highly incident tested prefix, but M does not order exact achievable minima: a later lower-M pair can still strictly improve. No probability of success or eligible-pair coverage fraction follows from32 tests. If64 additional starts finish on the same65 state with no pair improvement, curtail unchanged suffix spending and report only the tested source-bound prefix. If a pair improves, measure the exact lower U, subsequent row gains, accepted moves and charged cost; a lower invalid incumbent alone does not justify an automatic third allocation. ## Structurally different alternative if the suffix has no signal

A restricted exact three-row neighborhood can add an interaction unavailable to every two-row move without adding random restarts or uphill policy. This is a separate design candidate, not an allocated fallback. Select at most16 distinct row triples induced by current violated triples, deterministically ordered by exact removed-triple union incidence and row labels. With U65 there are at most65 such induced row triples, but this design does not inspect which ones occur. Each selected row's restricted column domain contains its current columns plus the least unary-cost missing columns, breaking ties by column, until it has four columns. Compute those unary costs after removing the three rows. The domain always includes the current assignment; it is not a full-grid three-row optimum.

Three full rows have216 load2/2/2 assignments over four columns per row. A block meeting the singleton has total load5 and requires all three1/2/2 orientations, at most432 assignments. The exact score has retained U, all unary terms, all three pair-cross terms, and an additional ternary term for one new point in each of the three rows. That last term is essential: unlike two rows, three new points can be collinear. Precompute its4×4×4 direct-determinant boolean table and the three4×4 retained-point cross tables. Same-row two-new triples with an off-row point remain impossible. Stream restricted `(X,Y,Z)` assignments in tuple-lexical order and retain the minimum `(score,X,Y,Z)`; nonnegativity permits the first fully scored zero exit in that lexical stream. Commit strict improvements only, and preserve the original row/point invariants and zero priority.

At most16 blocks give6912 restricted assignments, at most110592 retained-point pair-cross determinant checks (three16-entry tables times at most144 retained points per block),1024 ternary determinant checks, and176416 complete-index line visits for unary/base extraction, apart from bounded per-assignment sums and any accepted-state rebuilding. These are design ceilings, not a runtime or usefulness measurement. Independent tiny examples must first establish a genuine reachable pair-stuck/three-row-improving falsifier or clearly label a weaker restricted-neighborhood control example. Its restricted domains and16-block selection support only that finite family, not a full three-row local minimum or general exclusion. Review its candidate-domain bias and ternary correctness before preferring it to another pair suffix. No code, source-point selection or actual geometry for this alternative is authorized here.
