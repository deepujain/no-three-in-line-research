# Row-block pilot: completed-boundary checkpoint and zero-candidate priority

Design-only addendum to immutable proposal `research/from-scratch-row-block-breakout75-design.md`, SHA-256 `23a31e84ead3756cbcc367ccf2f650cee0695519345f43a729ae07924e2fe5b3`. No worker, search, checkpoint import or resume CLI is authorized here. This specifies a bounded shutdown artifact so an accepted pilot need not be replayed merely to recover its state. Any future continuation still requires a separate review and explicit Root allocation.

## One transaction boundary

The committed boundary contains the sorted current points, complete unweighted/weighted scores, deficient row, sorted best-unweighted points and score, nondefault line weights, RNG state, completed-transition number, stagnation counter and complete logical counters. It is created initially only after initialization and the complete initial index/score. Before that, shutdown has no completed checkpoint. The pair-line index is derivable and is not serialized.

At transition start, save the committed RNG state. Candidate selection, all32 migration samples when applicable, the next index and scores, best-state update, stagnation update, and any due complete penalty update are provisional. A positive-score transition commits only after all these parts finish. Increment accepted/completed counters only at this commit. Selection is not acceptance. Any cooperative deadline, partial sample/index, cap or error before commit leaves the prior committed state, weights, best and logical counters intact and restores its RNG state. Attempted/aborted work is retained separately in the report and never represented as completed transitions. There is no pending-penalty checkpoint phase.

Committed weight maps are not mutated. If a penalty update is due, precheck the entire update against the key/value caps; stage a new map by copying the committed map and applying all increments to the copy. Build the new weighted score and logical counters before commit. If staging is interrupted or a cap fails, discard the staged map and abort the whole transition. Retain the old boundary; do not adopt a new point state with old weights and an unspecified pending update. A single boundary-reference replacement adopts the completed transaction. After commit, the live RNG agrees with the captured RNG state after the selection's last random draw; penalty updates are deterministic and draw no random numbers. No cooperative checkpoint occurs inside the final reference replacement. A killed process may leave no final artifact; it must not produce an accepted receipt from an incomplete write.

This refines the proposal's phrase "accepted transition": an evaluation-selected candidate becomes accepted only at the complete transaction boundary. At most two weight maps are live during penalty staging, in addition to at most two pair-line indexes. The engineering memory envelope must account for this temporary duplication.

## Zero takes priority at every completed index

Whenever a complete initial or proposed next-state index reports U=0, stop ordinary search immediately. For a proposed next state, commit that fully scored zero state, RNG and best state without optional penalty work; reset stagnation. Handle it before the next iteration or its search-deadline test. Zero cannot require a penalty increment because it strictly improves any positive best score.

If the main soft deadline permits starting validator one, run it. If validator one finishes after that deadline, do not start validator two. If validator two starts in time and completes, save the dual-accepted witness immediately, even if it completed after the soft deadline, and before optional checkpoint/report/final-pin work. Disagreement or incomplete validation never gives a verified witness. Regardless of whether validation can finish, the raw committed zero state remains eligible for the shutdown checkpoint, explicitly labeled `unverified_zero_candidate` until both validators accept that exact identity. A raw checkpoint may support a separately allocated Root audit later; it is not a certificate or an automatic validation allocation.

Do not overwrite or withdraw a saved dual-verified witness because later checkpoint/report/pin work fails. Report the later failure separately; independent acceptance still checks the witness and receipt scope. No automatic retry follows either result.

## Bounded shutdown artifact

Use one separate `completed-boundary.json` in the fresh output directory, not inside the1-MiB report allowance. It is written once on shutdown, never read by the pilot, and contains only the latest committed boundary. Serialize compact ASCII JSON with stable field order and sorted points/line records; nondefault weights are `[a,b,c,w]` records sorted lexicographically by the canonical line key. There are at most65536 records; |a|,|b|<=74, |c|<=10952 and1<w<=65535. Each compact record plus its separating comma needs at most22 bytes, so this component needs at most1441793 bytes including the outer brackets. Two149-point state arrays, RNG and strictly bounded metadata keep the whole artifact below a hard2-MiB byte cap. No indexes, trace history or arbitrary exception text are included.

For the pinned Python runtime, serialize the exact `random.Random.getstate()` version3 triple: version3,624 unsigned32-bit words followed by an index in[0,624], and null Gaussian cache. These operations use no Gaussian draw. This is a runtime-specific state receipt, not a portable RNG promise. Record exact source/runtime/manifest identities, grid/target/seed/policy constants, completed-transition and stagnation counters, total completed penalty events, current/best state hashes, current/best score fields, validation classification and boundary schema version. Bound the remaining metadata at16KiB, and all logical count fields to unsigned64-bit integers. Work counters for aborted evaluations belong to the report, outside the logical continuation boundary.

Build and size-check the entire serialized byte string before publication. On oversize or schema failure, report checkpoint failure and do not publish a truncated substitute. Write to a fresh same-directory temporary file, flush/fsync, then atomically rename; final report records byte size and SHA-256. A crash during writing may leave an unaccepted temporary file. No crash-durability claim is made for the directory. A partial or absent checkpoint is not a resumable state, and a valid witness saved earlier remains separate.

For the proposed25-second soft pilot, stop transition construction cooperatively at23 seconds from worker entry, reserving the final2 seconds for optional validation and bounded shutdown work within the same25-second soft envelope. Validator-start decisions use the25-second deadline; witness publication follows the priority rule above. Serialization and atomic publication are bounded finalization work and can overrun the soft deadline; the unchanged30-second owned/256-MiB guard is still authoritative. There is no guarantee that an external kill leaves a checkpoint. Pins and final receipt acceptance must expose any incomplete or failed shutdown. This allocation tightens useful search time and does not expand either guard.

Synthetic lifecycle gates must interrupt before/after selection RNG draws, during migration sampling/index construction, during weight-copy/update staging, after a candidate zero index, after validator one, during/after validator two, and during checkpoint serialization/write. Compare checkpoint state+weights+RNG+logical counters exactly with a separately captured completed boundary, including a cap-triggered rollback and an interrupted penalty update. Checkpoint publication must not require re-evaluating actual n75 geometry. A synthetic split-run test may restore its own tiny checkpoint in a test-only oracle and compare the next completed trajectory with an uninterrupted tiny run; this does not add a production resume API.
