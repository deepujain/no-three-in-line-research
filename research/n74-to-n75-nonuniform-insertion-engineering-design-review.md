## Geometry and family boundaries

For every gap c in 0..74, x maps to x+[x>=c]. This is an injective increasing map from 0..73 onto 0..74 except c. The same statement holds for rows. Thus the mapped source has 148 distinct points, and adding (c,r) gives 149 distinct points with exactly one deficient row r and one deficient column c. Consequently different gap pairs actually give different literal target sets: those two deficiencies identify their gap. The family size is exactly 5,621 after removing the four pairs in {0,74} squared; no symmetry quotient is implicit.

A triple either has three mapped old points or has the inserted point and two mapped old points. These classes are exhaustive and disjoint. For k source coordinates v1<...<vs on one axis, the correct constant-shift gap intervals are [0,v1], [v1+1,v2], ..., [vs+1,74]. All are nonempty. Equality belongs to the interval ending at the source coordinate because the comparison is >=. Contraction code that omits cuts equal to occupied coordinates cannot be reused unchanged.

For an old triple, fixed x- and y-intervals fix all six mapped coordinates, so one exact determinant decides the entire rectangle. There are at most 4 by 4 rectangles. In each of the four products of the two outer intervals, all three x-shifts agree and all three y-shifts agree. This is a translation of the source triple, so the determinant remains nonzero when the source is valid. Skipping these four rectangles is sound only after independent source validity is established. This shortcut concerns broad rectangles and is distinct from removing the four global both-boundary gap choices.

For an old pair, fixed intervals fix p' and q'. With A=q'x-p'x and B=q'y-p'y, collinearity with (c,r) is A*r-B*c+B*p'x-A*p'y=0. If the pair was horizontal, its common mapped row cannot equal the inserted row; the vertical case is analogous. A pair that was neither horizontal nor vertical remains so because each axis map is strictly increasing. Its integer line points are exactly p'+t*(A/g,B/g), where g=gcd(abs(A),abs(B)) and t is integral. Signed ceil/floor intersection with both rectangle coordinate ranges is therefore sufficient and necessary. The implementation must avoid division assumptions for negative directions and must explicitly ignore the four excluded solutions.

## Coverage certificate and positive acceptance

The proposed bit index 75*c+r is unambiguous. Multiplying a column-repeat integer by a contiguous row mask produces the intended rectangle because each shifted row mask lies in a separate 75-bit band. Initialize only the included gap bits. A zero old-triple rectangle or a pair-line point may remove only still-uncovered included bits and assign their first obstruction. This bounds the number of assigned records by 5,621 without retaining scores or rescanning all gaps per rectangle.

Before declaring a negative family closure, independently check every included gap's stored obstruction: source indices must be in range and distinct; map exactly those two or three source points; for a pair obstruction add the specified inserted point; verify all points are target members and distinct, and verify the exact determinant is zero. Require exactly one record for each included gap and no records for the four excluded gaps. At most 5,621 tiny determinant checks suffice. A verified full obstruction cover can close the family before all source triples or pairs are enumerated, but must be called certificate-complete, never a complete score census.

Remaining bits can be proposed as positive candidates only after both triple classes finish. A deadline with unexcluded gaps establishes neither a positive nor a complete negative. Reconstruct a candidate, require both full exact validators, and persist the validated witness immediately. A second validator that finishes near the deadline must be followed by the witness save before optional bookkeeping. Final identity or deadline failures clear completion/closure even if a saved witness remains available for later independent assessment.

## Concrete work and storage bounds

There are C(148,3)=529,396 old triples. At most 16 rectangles each gives 8,470,336 determinant setups; skipping four translated rectangles reduces this to at most 6,352,752. Repeated source x/y values only reduce interval counts. There are C(148,2)=10,878 old pairs and at most 97,902 pair rectangles. Across one pair's rectangles, the column-scanning oracle visits at most 3*75=225 columns. Primitive lattice enumeration cannot exceed that bound since A/g is a nonzero integer, giving at most 2,447,550 visited line points in all. These are ceilings, not a 25-second timing guarantee.

At most 2,850 column intervals are precomputed. Each column-repeat integer is at most 5,551 bits; a rectangle or uncovered mask is at most 5,625 bits. The design's conservative 704-byte logical bound per mask totals 2,006,400 bytes, excluding interpreter overhead. A typical 30-bit-digit CPython integer of this width is under 0.8 KiB; 2,850 such objects use roughly 2.2 MiB plus container references and interval keys. A flat triangular list avoids tuple-key dictionary overhead. Optional 2,850 row masks each have at most 75 bits. A compact record table with one 32-bit slot for each of 5,625 gaps uses 22,500 bytes; encode kind plus two/three 8-bit source indices and reserve zero for absent. Use bytearray/explicit packing or verify array itemsize=4. Python tuple records would still be bounded but must be accounted for honestly.

All precomputation, source validation, geometry, record extraction and verification, candidate validation, hashes and publication share one separately allocated 25-second cooperative / 30-second owned / 256-MiB gate. Deadline checks must cover precomputation and certificate verification as well as geometry loops. Persist counters for triples started/completed, rectangle tests, pairs started/completed, pair rectangles, line points, assigned gaps, certificate checks, and final validator state, so interruption cannot masquerade as exhaustion. The owned guard remains necessary for native or uncooperative work. No second record, orientation loop, repair, target change or retry follows automatically.
