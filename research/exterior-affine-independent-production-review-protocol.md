# Independent exterior-affine production review protocol

Target design: `research/n74-exterior-unimodular-extension-bounded-design.md`, SHA-256 `8bb89141c3fb1b8ed5fb4282c6f2fa4bd07b3eea92358998f9805afe02ed686b`. This protocol prepares independent review only. The reviewer does not author production code or read the selected n74 source. All historical design and oracle files remain unchanged.

## Pure oracle interface

The separate `research/exterior_affine_independent_oracle.py` imports the frozen independent design helper and determinant oracle, not a production module. `expected_inventory(points,n)` accepts only synthetic n=4..6 inputs and returns canonical sorted source points; exact H/V and maximizing source-index witnesses; coefficient bounds; literal admitted/rejected direction maps; directions outside the proposed cutoff; canonical frames including an ordinary-frame label; every translation and deficient level set; occupied/distinct candidate choices; all eligible and exterior preimages with frame witnesses; every direct collinear old-pair obstruction; and the valid exterior preimage set.

The admitted-set oracle enumerates the full universal coefficient box [-n,n]^2 before classifying candidates by H/V. Therefore the H/V shortcut is tested against a larger independently enumerated domain, not repeated as the oracle's generation rule. Direction values, occupancy, widths and source-index extrema are computed directly. Frames and inverse arithmetic reuse the immutable design helper already compared with all small integer matrices. Literal tuple sets define expected candidates and certificates without a production encoding dependency.

`check_width_obstruction(points,u,indices,n)` verifies any supplied two-index rejection witness has projection difference greater than n; it does not require the production witness to be an extreme pair. `check_point_obstruction(points,q,indices)` verifies a distinct new q and an exact collinear old pair. Neither function trusts production width summaries or cached line tables. Production indices should refer to lexicographically sorted points; the adapter can normalize a different documented convention before comparing.

## Required source and production comparisons

On every valid full-axis synthetic n4 source, compare the production result with the complete oracle inventory. Verify all coefficient candidates are admitted or rejected exactly once, every cutoff follows from source-member H/V witnesses, gcd/sign reductions are exact, equality at width n remains admitted, and rejection occurs only above n. Compare complete source-projection extrema/counts for admitted directions; independently check every rejected-direction certificate. Admitted count at most four unsigned is a theorem consequence after source validity, not a reason to stop enumeration early.

Compare all canonical unordered row pairs, determinant +/-1 filtering, exclusion of the ordinary axis pair, exact translations, and deficient coordinate levels. Verify at most four raw placement/cell choices per frame including occupied choices, then check exclusion of an occupied singleton intersection. Compare q=A^-1(z-t), forward reconstruction, protected-box classification including boundaries, preimage deduplication and preservation of at least one witnessing frame per q. Compare the complete exterior-q set and every produced collinear pair. A first obstruction may differ from the oracle's first pair; its actual geometry must be valid. For any surviving q, compare full target determinant validity and the dual-validator/save path.

Compare reversed/shuffled source order and signed/permuted frame rows against the canonical result. The invariant is the original-coordinate q set, not identical target coordinates before symmetry normalization. Apply the mod3 theorem only for n>=4; an implementation exposing n2/n3 tests must either reject those orders or use a separately sound general path without the eight-direction assertion.

## Invalid, partial and lifecycle cases

Reject duplicate/out-of-range/noninteger/wrong-axis/wrong-cardinality sources and every full-axis collinear synthetic source before invoking the width theorem or applying its eight-direction bound. Test missing H/V witness, wrong source index, swapped axis claim, nonmaximum claimed H/V when exact maxima are promised, coefficient-domain omission, an admitted direction with unchecked projections, duplicated/missing rejected direction, false strict-width inequality, and nonprimitive direction leakage.

Mutate frame determinant/sign/order, omit a translation, falsify an inverse, admit an occupied old point, misclassify a protected boundary, duplicate q under different frames, delete a q witness, and corrupt a collinear-pair certificate. A negative result is valid only after exhaustive direction/frame/candidate inventory and valid obstruction coverage, or a separately proven empty nonordinary/exterior family. Partial inventory, merely reaching the maximum direction count, or a deadline with remaining candidates proves no exclusion. Protected points are scope-excluded, not counted as certified impossible solely by that filter.

Inject deadlines before and during source validation, H/V extraction, rejected/accepted projection checks, direction-certificate extraction, canonical pair enumeration, translations/candidate extraction, q verification, pair tests, independent certificate validation, final pins and output. Interrupt after a direction is admitted but before its next counterpart is examined, and after one q is rejected while another remains. Neither may be marked complete. A successful second candidate validator must be followed by saving before optional work; final identity/time failure clears whole-family completion/closure while retaining an already saved witness.

## Handoff and artifact boundaries

Before comparison, record exact production/helper hashes and read their source. Use only pure synthetic entry points; do not call the selected-source CLI or loader. Keep author tests and evidence immutable, writing independent comparison helpers and evidence separately. A source/tiny PASS must list actual comparison counts and any limits; it cannot certify actual runtime feasibility or allocate selected-source geometry. Lifecycle/containment and source-specific prior-scope reviewers remain independent. Production implementation and any actual inventory require their own explicit Root decisions.
