# Streamed near-quarter-turn model

Research Software Engineer, gpt-6.1-terra/high per parent assignment, 2026-11-27. Implementation: `src/near_quarter_model.py`, SHA-256 `b53adcf159cd7d32416e02ae970a339afcb40442107c966ef6393680d479838a`; tests `tests/test_near_quarter_model.py`, SHA-256 `7a6c77363155e1958a17eddadd38ec3cd1d9a6a938bca1469c8e85f72a4243b4`. Family and motivation are sourced to [Prellberg, arXiv 2602.07751 §3](https://arxiv.org/html/2602.07751#S3) and explained in `research/next-exploration.md`.

`orbit_map(n)` deterministically sorts the four-point off-both-diagonals quarter-turn orbits, followed by main-diagonal half-turn pairs; the anti-diagonal is empty. IDs are 1-based. `family_counts` provides the source and line-generator hashes plus the SHA-256 of compact JSON containing the complete ordered orbit array, so a stored assignment is reproducible. For n=79 the algebraic orbit count is 1,521 four-orbits and 39 diagonal pairs. No n79 model, large geometry enumeration, solver or search was run for this implementation.

`weighted_lines` streams maximal lines and maps each to its exact variable multiplicities. It can take one representative of each half-turn line pair because every allowed orbit is itself half-turn invariant. It does not quotient by quarter turns; the diagonal exception forbids that inference. It deliberately does not globally deduplicate weighted signatures, avoiding an unbounded in-memory hash table. `streamed_cnf` requires optional python-sat and emits exactly (n−1)/2 chosen four-orbits, exactly one diagonal pair, and every streamed weighted capacity ≤2. The total is 2n; line capacities include every row and column for n≥3, so they force exactly two points on each. A coefficient 2 forbids co-selection of every other positive term; coefficients >2 force the variable false; coefficient 1 terms use a sequential at-most-two counter. Cardinality auxiliaries are allocated from one IDPool above all orbit IDs. Although a real straight line meets each actual square orbit or pair in at most two points, synthetic coefficient ≥3 is still tested defensively.

`check_candidate` expands orbit IDs and uses both independent exact verifiers, returning a full certificate only when count=2n and both accept. An UNSAT result from any solver fed this model would concern this restricted family only and would require correct encoding, solver and independent proof checking before formal infeasibility claims. No UNSAT or witness is claimed here.

`.venv/bin/python -m unittest discover -s tests -p test_near_quarter_model.py -v` passed five tests. For n=3,5,7 all orbit assignments were checked against independent determinant geometry and against line constraints both before and after half-turn quotient; the CNF was checked for every orbit assignment with variables fixed as SAT assumptions. Tests include the valid six-point n3 fixture, and synthetic weights 1,2,3. System Python passes the three standard-library tests and skips the two optional PySAT tests.

**Required preflight before large use:** no function imposes an automatic solver memory gate, and streaming clauses into a solver does not bound that solver's memory. Count/measure the n79 line stream and build under a separately scheduled process and explicit 30-second, 256-MiB proposed gate, with a host-enforced guard and margin for concurrent workers. Validate a primary n71 or n73 `rct4` witness against the map before relying on the branch. Do not silently drop line constraints on a memory limit. The independent mathematician approved the exact model and encoder in `research/near-quarter-review.md`. Published-fixture validation and the resource/build gate remain outstanding; no large model or search may launch before those gates.
